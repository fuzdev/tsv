# The tape: tsv's binary parse wire

The **tape** is the span-only JSON wire (the tree every `parse_<lang>` export returns) laid down
as little-endian `u32` words, so a JS host can build the tree `JSON.parse` would build from the
JSON text — the same keys, in the same order, with the same values — without parsing any text.
It is derived entirely from the AST schema table (`crates/tsv_wasm/types/tsv_ast_schema.json`,
crates/tsv_wasm/CLAUDE.md §TS Type Maintenance) and a committed list of fast shapes
(`crates/tsv_wasm/types/tsv_tape_shapes.json`).

Its pieces:

| piece | where | what |
| --- | --- | --- |
| the schema | `scripts/tape_schema.ts` | the table's entries as **tape entries**, each field's **encoding**, the fast shapes, `SHAPES_HASH` |
| the producer | `tsv_lang::tape::TapeSink` / `TapeWriter` (`crates/tsv_lang/src/tape/sink.rs`, `_tape` with `_json`), written by each wire writer's tape copy (`tsv_css::__private::write_tape`, `tsv_ts::__private::write_tape`, `tsv_svelte::__private::write_tape` — each crate's `_tape` feature; Svelte's composes the other two's for its islands) | the internal AST → tape, from the walk that writes the JSON wire, its refs true offsets ([§A direct writer](#a-direct-writer-true-offset-refs)); what every binding ships |
| the oracle | `tsv_debug::transcoder::Transcoder` (`crates/tsv_debug/src/transcoder/`) | the JSON wire → the canonical tape, in Rust, with no recursion — the second implementation every direct tape is graded through ([§The transcoder](#the-transcoder-the-oracle)); shipped nowhere |
| the decoder | `crates/tsv_wasm/npm/tape_decode.js` | tape → tree (the span-only wire's, or in loc mode the `loc`-bearing wire's), GENERATED by `scripts/tape_gen.ts` |
| the Rust format | `tsv_lang::tape` (`crates/tsv_lang/src/tape/`, `tsv_lang`'s `_tape` feature) | the format's types and constants (encodings, header words, value tags) and, in `shapes.rs`, the schema as Rust statics, GENERATED by `scripts/tape_gen.ts` |
| the reference encoder | `scripts/tape_encode.ts` | tree → tape in JS, with a task stack rather than a recursion; the format's executable statement on the JS side, shipped nowhere |
| the printer | `tsv_debug::tape::tape_to_json` | tape → JSON bytes, the transcoder's inverse, shipped nowhere |
| the bindings' export | `tsv_arena`'s `parse_tape!`, in `tsv_napi`, `tsv_wasm` and `tsv_ffi` | parse → the writer's tape, as words ([§Where it ships](#where-it-ships)) |
| the adapter | `crates/tsv_wasm/npm/tape_engine.js` | a raw tape export → the npm facade's `parse_<lang>` |

The gates: for the oracle and the format, `npm run check:tape` (docs/audits.md §Tape Gate),
`tests/tape_roundtrip.rs`, the transcoder legs of `tests/depth_limit.rs`, and at conformance
cadence `npm run tape:corpus`; for the direct producer — what ships — the same, over its tapes
([§Grading a direct tape](#grading-a-direct-tape)), and the bindings' in-crate tests (each
export's words are its language's writer's); over the shipped packages, the package suites (the
decoded tree, stringified, is the native CLI's span-only wire byte for byte) and
`npm run engines:audit`'s parse leg (the two engines' `parse_<lang>` equal, over the fixtures and
the corpus snapshot).
`npm run check:ast-schema` holds the two generated files to the table and the shape list.

## The schema

**Tape entries.** One per table entry that a wire object can be (the comment mixin is none), its
fields in wire order, the `loc`-only fields (`presence: locations`) dropped — the tape carries
the span-only wire alone; `{locations: true}` is the decoder's loc mode over the same tape
([§Decoding](#decoding)). Where those fields sat rides each entry as two flags outside the
format (no tape byte, no part of `SHAPES_HASH`): `loc`, which a table must place right after
`end` on exactly the entries whose `start` and `end` are required offsets, and `name_loc`, right
after a required `name`; the schema refuses a table that places either anywhere else, carries
another `loc`-only field, or folds two entries that disagree on them. An entry whose fields,
encodings and mask bits are identical to an earlier one's of the same `type` (or, for a
`type`-less entry, identical outright) folds into it: a named variant that encodes like its base
never needs an id of its own.

**Mask bits.** A field carries a mask bit when a record of its entry may leave it out in either
dialect: its `presence` or its `vanilla_acorn` presence is not `always`. A record's
**presence mask** holds the bits of the fields it carries. At most 20 per entry.

**Fast shapes.** A fast shape is one `(entry, mask)` pair, numbered from `1` in entry-then-mask
order: every entry's all-required mask (`0`), and every pair `tsv_tape_shapes.json` lists. The
list is generated — `npm run tape-shapes:update` writes every non-zero mask the fixture wire
carries — so the masks real code takes decode through a literal, and any other valid mask still
decodes through the entry-generic record. `npm run check:tape` reports the records whose mask is
off the list; an update folds them in.

**`SHAPES_HASH`** is FNV-1a over a canonical text of the format version, every tape entry and
every fast shape. The transcoder writes it into each tape's header and the decoder refuses a tape
whose hash is not its own, so a tape and a decoder from different tables or shape lists never
meet silently. **`TAPE_FORMAT_VERSION`** (`scripts/tape_schema.ts`, generated into both outputs)
moves by hand when this document's rules change.

## Layout

```
header   8 words
body     N words      the root record
pool     M bytes      UTF-8, every string a ref does not take from the source
```

Every word is a little-endian `u32`; a signed word is its two's complement. The whole tape needs
4-byte alignment and nothing more (a float is two words, read through a scratch view), so a host
can view it in place. The header:

| word | value |
| --- | --- |
| 0 | the magic, the bytes `TSVT` |
| 1 | `TAPE_FORMAT_VERSION` |
| 2 | `SHAPES_HASH` |
| 3 | N, the body's word count |
| 4 | M, the pool's byte count |
| 5 | `0` |
| 6 | the pool's length in UTF-16 code units |
| 7 | the source's length in UTF-16 code units — the text the tape's offsets index |

## Records

A record is an object (or `null`) in a position the schema types as a node or a `type`-less
object. It starts with a **header word** (signed):

| header | the record | then |
| --- | --- | --- |
| `0` | `null` | nothing |
| `≥ 1` | a fast shape: its id | the present fields, in field order |
| `-1` | a self-describing object | a key count, then per key a string ref (its text) and a tagged value |
| `≤ -2` | an entry-generic record: `-(2 + (mask × 1024 + entry))` | the present fields, in field order |

A typed record's body depends only on its entry and mask, so a fast shape and an entry-generic
record of the same pair carry the same body: the header is all that differs. The
self-describing record carries what no entry can: an object with no `type`, or a `type` no entry
holds, or keys or values its entries refuse — the `customElement` data of `<svelte:options>`
(user-chosen keys, a data `"type"`), a regex literal's empty `value` object — which is why it
carries key TEXT, not key indices.

Records are pre-order: a record's header, then its fields, a nested record's whole body inside
its parent's at the field's position. A producer writes the header when the object closes.

## Field encodings

Each field's encoding follows from its kind, its string class and its nullability:

| encoding | from | words |
| --- | --- | --- |
| `type` | `kind: type` | none — the entry's constant |
| `offset` | `offset` | one, unsigned |
| `boolean` | `boolean` | one, `0` / `1` |
| `number` | `number` | two, the `f64`'s little-endian bytes |
| `null` | `null` | none |
| `own` | a string of class `own` behind its entry's required `start` and `end` | none — the source between the record's own `start` and `end` |
| `keyword` | a string of class `keyword` | one, the index into the field's `values` |
| `ref` | any other string (`slice`, `cooked`, `pooled`, an `own` one ahead of its span) | two, a string ref |
| `ref_nullable` | the same, `nullable` | two, a string ref or the null ref |
| `strings` | `strings` | a count, then that many string refs |
| `record` | `child`, `object` | a record; an `object` field holding a `type`-less entry names it, a `child` takes any |
| `list` | `list`, `comments` | a count, then that many records |
| `value` | several kinds, `data`, or a nullable scalar | a tagged value |

The string classes other than `own` and `keyword` are producer hints, not bytes: every ref is
resolved by one rule (below). `own` and `keyword` are promises a value can break — an `own`
string that is not the source between its offsets, a keyword outside its vocabulary — and a value
that breaks one fails its entry (§Producing a tape).

### Tagged values

A tag word, then:

| tag | value | then |
| --- | --- | --- |
| `0` | `null` | nothing |
| `1` / `2` | `false` / `true` | nothing |
| `3` | a number | two words, an `f64` |
| `4` | a string | a string ref |
| `5` | an array | a count, then that many tagged values |
| `6` | an object | a record (in a position that names no entry) |

### String refs

Two words `[a, b]`, both in UTF-16 code units:

- `a ≥ 0`: the source text `[a, b)`;
- `a = -2³¹` (`i32::MIN`): `null` (`b` is `0`);
- any other `a < 0`: the pool text `[-1 - a, b)`, the pool decoded once as UTF-8.

The **source** a tape is written against is the text the wire's offsets index: the parsed
source, less a leading byte-order mark for a Svelte or CSS document, whose wires elide it as
Svelte's `parse` and `parseCss` do (crates/tsv_wasm/CLAUDE.md §The Span-Only Wire). Offsets
that count UTF-16 units index a JS string directly; the transcoder maps them to bytes.

A ref names its TEXT, not where that text was found: any source slice whose text equals the value
is a valid ref, and the pool may hold its entries in any order, a text more than once. The
offline encoder and the transcoder write one canonical choice
([§Producing a tape](#producing-a-tape)), a direct writer another
([§A direct writer](#a-direct-writer-true-offset-refs)), and every decoder reads them alike.

Lone surrogates never reach a tape: the wire carries U+FFFD where a source spells one
(docs/conformance_svelte.md), and the npm facade refuses an ill-formed source. A wire string that
holds one anyway is refused by both producers — the pool is UTF-8.

## Producing a tape

The offline encoder and the transcoder follow these rules, so they write the same bytes for one
wire — the tape's **canonical** form. A direct writer follows them too but for where its refs
point and how its pool is laid out ([§A direct writer](#a-direct-writer-true-offset-refs)).

**An object's entry.** An object in a record position tries its **candidates** in table order:
the `type`-less entry a field names, else the tape entries of its `type` value. It takes the
first whose fields admit its keys — in field order, skipping only fields with a mask bit — and
whose encodings accept its values (an integer offset in `u32` range, a boolean, an `own` string
that is the source between the object's offsets, a keyword in its vocabulary, …). An object no
candidate takes is written self-describing. A wire the writers emit takes its first candidate
but where a variant differs from its base (`Literal` against the fused literal Svelte builds for
`<svelte:element this="…">`, whose `raw` is not the source).

A typed entry's keys ahead of its `type` (`Root`'s `css`, `js`, the directives' `start` and
`end`) take one encoding whichever entry they belong to — the schema refuses a table where they
would not — so a streaming producer encodes them before it knows the entry.

**The scope of a string.** A ref is a source slice when its text occurs in the record's
**scope**, else a pool entry:

- a record's **own span** is its `start` and `end` when both are integers, `start ≤ end`, the
  end within the source, and neither splits a surrogate pair;
- a record's refs search its own span, or, without one, the scope it inherited;
- a value under the record inherits the record's own span when both `start` and `end` come
  before the value's key, else the record's own inherited scope; the root inherits the whole
  source.

The slice is the text's **first occurrence** wholly inside the scope (an empty string sits at the
scope's start); the pool entry appends the text to the pool.

**When refs resolve.** A record's refs — its fields', its tagged values', its keys' — resolve
when the record closes, in the order the record wrote them, after every nested record's. The pool
is the concatenation of the pooled texts in that order. (A record can name a string before the
span it is searched in: a comment's `value` precedes its `start`.)

**What byte equality between the producers assumes.** The writers' JSON: compact, integers as
plain digits, no duplicate key, no integer-like key. The offline encoder reads `JSON.parse`'s
tree, which has lost a number's spelling, a duplicate key and the text order of integer-like
keys; the transcoder reads the text. Both decode to the same tree either way.

### A direct writer: true-offset refs

A language crate's wire writer can write the tape itself, from the walk that writes its JSON
wire, into `tsv_lang::tape::TapeSink` (crates/tsv_lang/CLAUDE.md §Modules, `tape`): the writer's
body is mounted a second time with the tape as its sink, each site naming what its JSON literal
means on the tape — `tsv_css` as a token spec per site, `tsv_ts` and `tsv_svelte` by handing the
literal itself to a compile-time reader (`tsv_lang::tape::literal_ops`) that resolves its keys
against the schema and leaves each value to the field its key declared (crates/tsv_css/CLAUDE.md,
crates/tsv_ts/CLAUDE.md and crates/tsv_svelte/CLAUDE.md §Distinctives, the twin-mounted writer).
The Svelte writer's tape copy writes the embedded TypeScript and CSS through those writers' tape
copies, into the one document. This is the producer every binding ships (§Where it ships). It
knows what the transcoder has to search for, so it writes:

- **records** pre-order, each header slot reserved when the record opens and written when it
  closes, from the presence bits its fields set; each list's count slot patched at its close;
- **a string the writer borrowed from the source** as the slice it occupies — its **true
  offset** — whatever the record's scope, and **any other string** appended to the pool at once,
  in write order;
- every other encoding exactly as above: offsets as emitted, a keyword by its index (resolved
  from its text at build time, so a word outside the vocabulary fails the writer's build), a
  number as its `f64`;
- **a record's typed entry from the site**, not from its keys: a record whose keys lead its
  `type` (`Root`'s `css` / `js`, a directive's `start` / `end`) opens before them, and a named
  variant (`Literal/SvelteFusedLiteral`, whose `raw` is not the source) opens as itself;
- the encodings only a Svelte wire carries — a tagged-value field holding an array (an
  attribute's text-and-tag sequence: the array tag, a count, each record behind its object tag),
  a `strings` field (a directive's modifiers), and a self-describing record (`customElement`'s
  data) — through the sink's `t_value_list_open`, `t_list_ref` and `t_object_open` /
  `t_object_key` / `t_object_close`, a frame like a list's, so the sink counts the keys the
  writer writes, each key leaving a tagged value pending that the next data call writes.

Where the canonical rule finds a text's first occurrence in scope, the direct writer has the
occurrence it read, so the two tapes differ only in refs and pool, and decode to one tree. The
sink refuses a tape the writer left inconsistent — a key of an entry other than the open
record's, a keyword written as its word, a record, list or self-describing record left open, a
self-describing record's key with no value (before the next key or at the close), a boolean or a
nested self-describing record written as its value with no key ahead of it, a string outside the
`strings` list that counts it — in every build, so no such tape is handed out.
Every count a tape carries (a list's items, a self-describing record's keys, a `strings` field's
strings) is the sink's count of what the writer wrote through the counted forms (`t_object_key`,
`t_list_ref`), never a number the writer hands in. What the sink cannot see is a field written
positionally (a head's `start` and `end`, an element's `name`) whose place the schema moved, which
the Svelte writer's tape copy checks against the schema at build time (`cargo check` and clippy
included, but for the const-generic directive head's check, which only a codegen build
evaluates), a self-describing record's string or number value or embedded expression written
with no key ahead of it (the sink writes it as plain words, which the decoder reads in a key's
place) or a `null` value with none (the sink writes nothing), and a key or a string of a
`strings` field written as a plain ref where its counted form belongs — which only the roundtrip
gates catch.

### Grading a direct tape

A direct tape is not byte-equal to the transcoder's, so it is graded through the transcoder as a
canonicalizer: for the same parse's JSON wire `json`,

- its words (`TapeSink::finish_words`, the form a binding hands its host) are its bytes;
- `tape_to_json(direct) == json`, byte for byte — the direct tape lost nothing a decoder reads;
- `transcode(tape_to_json(direct)) == transcode(json)` — which the first makes follow, checked
  anyway, since it is the canonical form's own statement;
- both decoder paths read the direct tape back to the tree `JSON.parse` makes of `json`, key
  order included.

`tests/tape_roundtrip.rs` runs the first three over every Svelte document of the fixture tree (its
template, `<script>`s, expression islands with their comment attach and `<style>`, in one tape),
every CSS one (each `.css` input, and each `<style>` body read as a stylesheet of its own) and
every TypeScript one (each `.ts` input at both goals where it parses at both, each `<script>` body,
and expression islands under a comment attach); `npm run check:tape` all four over every fixture
document, the Rust half's failures failing the run; and `npm run tape:corpus` all four over the
corpus's files (`tsv_debug::tape::grade_svelte_direct_tape` / `grade_css_direct_tape` /
`grade_ts_direct_tape` is the Rust half of each); `tests/depth_limit.rs` writes all four at the
parsers' depth limits on the contract's stack, and the fuzzer every accepted mutant's.

## Decoding

The decoder (`decode_tape(bytes, source, language?)`) is generated: one small function per fast
shape builds its record as one object literal in wire key order (an `own` field slices the
source by the record's offsets), dispatched through a table by the header word — never one large
`switch`. Every other record goes through one iterative interpreter over generated descriptor
tables (`decode_tape_iterative` runs a whole tape through it), which builds an object key by key
in field order; a self-describing record's `__proto__` key is defined as an own property, as
`JSON.parse` makes one. The descriptor tables are `JSON.parse` of string literals, which an
engine reads faster at load than the same data as array literals.

**Loc mode.** Handed the document's language (`'typescript'`, `'svelte'` or `'css'`), a decode
builds the `loc`-bearing wire from the same tape: the tree `JSON.parse` makes of
`tsv parse --locations`'s JSON, key order included — what `parse_<lang>(source, {locations:
true})` returns. The rules are the ones `locations.js` reconstructs by, stated once in
`locations_core.js`, which the decoder imports: the language's line rule over the text the
offsets index (ECMAScript's terminators for TypeScript, LF alone for Svelte and CSS), the line
of each offset searched outward from the last one looked up, `loc` built right after `end` on
every record with offsets and a Svelte `name_loc` right after `name`, and — once the tree is
whole — Svelte's `character`-bearing positions (a shorthand attribute's identifier, a snippet
name, a block's simple-identifier pattern, an in-tag comment) re-stamped over the `loc` already
in place, so no key moves. Three readers build it:

- the **hot shapes** — the fast shapes the committed hot-shape list names
  (`crates/tsv_wasm/types/tsv_tape_hot.json`, cut by `npm run tape-hot:update` from a census
  of the author's own corpus collections, which the perf bench never times) — each have a
  generated twin of their fast function that builds the record, `loc` and all, as one object
  literal;
- a fast shape whose record nothing in loc mode changes (no offsets, no nested read) reuses its
  plain function;
- every other fast shape is read by one entry-generic loc reader over the descriptor tables, its
  nested reads still dispatched through the twins — so a shape off the list costs only its own
  record, never its subtree; the interpreter builds the same fields for every record it reads.

The twins size the decoder, which every `./parse` import loads, so the list holds only the
shapes most records take; it changes what is fast, never what is decoded. The plain functions
are generated unchanged beside them.

**Depth.** The fast path recurses, one call per nested record, and the parsers accept trees
deeper than a JS main thread's stack holds that recursion. A `RangeError` out of the fast path
re-decodes the same tape from its start through the interpreter, which recurses nowhere. That
recovery is clean by construction: the decoder's module state (the word views, the read position,
the source, the decoded pool and, in loc mode, the line table) is set from the tape before either
pass reads it, loc mode's lookup hint and Svelte host list are reset before the second, and the
float scratch is written before each read, so nothing an abandoned pass left behind is read again.
`scripts/tape_encode_test.ts` decodes a tree at the parsers' spine limit on a stack too small for
the fast pass and holds the result, a second decode of it and a decode of another tape to the
interpreter's, and the same three in loc mode.

**What it refuses.** A tape whose magic, version or `SHAPES_HASH` is not the decoder's, whose
length disagrees with its header, whose source length (word 7) is not the given source's — a
Svelte or CSS source handed over with the byte-order mark its wire elides, say, every slice of
which would read one unit early — or whose body holds a header or tag no shape or entry names;
and a big-endian host, whose typed-array views would read the little-endian words backwards.
Beyond those checks a corrupted tape is out of scope: a tape never crosses a boundary the
producer does not own.

## The transcoder: the oracle

The transcoder is the format's second producer, from the other side of the wire: it reads the JSON
text a writer emitted and writes the canonical tape (§Producing a tape), byte for byte the offline
JS encoder's (`npm run check:tape`). No binding ships it — the writers' tape copies do — so it is
`tsv_debug`'s, the oracle every direct tape is graded through ([§Grading a direct
tape](#grading-a-direct-tape)) and what the tape gates and `npm run tape:bench` time against.

`tsv_debug::transcoder::Transcoder::transcode(json, source)` reads the compact JSON once with an
explicit frame stack — an open object or array is a frame, so a nested value costs heap, not stack
— and writes the tape by the rules above:

- an object is written against one candidate at a time; each key is matched against the entry's
  next fields (the field order predicts it, the skipped fields being the ones its mask leaves
  out) and each value against its encoding;
- a key the candidate has no field for, or a value it refuses, rewinds the object — tape, pool,
  pending refs, read position — and writes it again against the next candidate, then
  self-describing; the attempt it settles on is remembered by its opening brace, so a rewind of an
  enclosing object re-reads it at that attempt, and each object is rewound at most once per
  candidate however deep the rewinds nest. A rewind still re-reads its object's whole text, so
  a chain of objects each refused only at its close costs time quadratic in the chain's depth —
  a shape only crafted JSON takes: the parsers' depth limits bound a writer's wire, and in it a
  refusal after an object's children (a type annotation carrying comments, which its comment-free
  variant refuses only at the comments) is rare and never nests;
- the keys ahead of an object's `type` are held until the `type` names a candidate, at most the
  most any entry carries (`PRE_TYPE_MAX`, generated with the tables);
- refs are reserved as they are read and resolved when their record closes, searched in the
  source with a UTF-16 → byte map (none for an ASCII source).

It refuses (`TapeError`) text that is not compact JSON, a string holding a lone surrogate, and a
source or tape past the format's sizes — a pool reaching `i32::MAX` UTF-16 units among them,
past which a pool ref's first word would read as a source slice. Its buffers keep their capacity
across calls.

## Where it ships

The npm packages' `parse_<lang>` takes the tape route, and it is their only parse: the
parse-capable packages' `./parse` entries (and `@fuzdev/tsv-parse-wasm`'s root) build
`create_parse_api`'s `engine.parse` with `create_tape_parse` (`tape_engine.js`), which calls the
engine's raw `parse_tape_<lang>`, decodes a returned tape with `decode_tape` against the text the
wire indexes (the source, less a leading BOM for Svelte and CSS), and passes a failure through.
No npm engine emits the JSON wire — `JSON.stringify` of the decoded tree is that wire, byte for
byte, which is how the packages' `tsv parse` (`cli.js`) prints it; the native CLI, the C FFI's
`tsv_parse_<lang>` and the Rust crates keep the JSON wire. Decoding is synchronous and calls
nothing in between, which is what each binding's hand-over relies on:

- **The export body.** `tsv_arena::parse_tape!` parses into the thread's stores and writes the
  tape with the language's own wire writer — its tape copy, `__private::write_tape` — into the
  thread's parked sink (`tape::with_tape_sink`, take and park), finished with
  `TapeSink::finish_words`: the tape as `u32` words, the header and body stored little-endian
  and the pool packed after them, the last word zero-padded — so the buffer is 4-aligned by its
  type on every binding, and each word's bytes in memory are the tape's bytes in order. The
  words are the sink's own buffer, the one the body was written into, lent to the binding for
  the call. The tape's exact length is its header's (`32 + 4 × words + pool bytes`), which the
  adapter views before decoding. Each binding turns on the language crates' `_tape` features
  from its `parse` feature alone, so the format-only builds compile no tape copy.
- **N-API** (`tsv_napi`): exactly the tape's words, lent from the parked sink and copied once
  into a `Uint32Array` the engine owns (napi-rs's `Uint32ArraySlice::copy_from`). Not an external
  arraybuffer over the addon's allocation: its napi finalizer runs only once the event loop
  turns, so a synchronous loop of parses would hold every tape it made until it yielded, beyond
  the garbage collector's reach.
- **WASM** (`tsv_wasm`): no copy — the export returns a `Uint32Array` view of linear memory
  over the parked sink's own words
  (`js_sys::Uint32Array::new_with_byte_offset_and_length` over `wasm_bindgen::memory()`'s
  buffer, never `Uint32Array::view`), valid until the next call into the instance; the
  instance keeps one tape-sized buffer, the sink's. No export reaches the writers' JSON copies,
  so they drop out of the bundles at link time.
- **C FFI** (`tsv_ffi`): `tsv_parse_tape_<lang>`, the uniform signature, its payload — the tape,
  or the `{"error": …}` JSON — a `Box<[u32]>` freed by `tsv_free_tape(ptr, len)`, with
  `*out_len` the byte length.

A tape the sink refuses out of a binding is thrown (`the parse does not fit a tape: …`): a tape
the writers write is refused only on size, or for a writer bug the sink caught.
