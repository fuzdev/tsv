# tsv_cli

> Production CLI for `tsv` — pure Rust, no Deno

Ships the `tsv` binary (defined in `Cargo.toml` `[[bin]]`). Depends on `tsv_ts`, `tsv_css`, and `tsv_svelte` (each with `convert` features), `tsv_lang` (the `estimated_ast_arena_capacity` parse-arena pre-size), `tsv_ignore` (discovery ignore-file matching) and `tsv_discover` (the per-directory prune/descend policy over it), plus `argh` and `bumpalo` (the parse arena) — nothing else; no `serde`, since the binary never deserializes (`--pretty` re-indents the writer's bytes). `tsv_debug` builds its own command set on this crate's `cli::` library surface; keep that surface stable.

For end-user invocation syntax see the [root CLAUDE.md §CLI Usage](../../CLAUDE.md#cli-usage---parse--format). For pattern background see [`docs/cli.md`](../../docs/cli.md).

## Public API

**Binary (`tsv`)** — `main.rs` parses `cli::TopLevel` from argv and dispatches, spelling out `argh::from_env`'s body (same early-exit contract: `--help` to stdout with exit 0, a parse error to stderr with exit 1) for one reason: to **pin the command name** argh prints in usage/help/error text to `tsv` rather than derive it from `argv[0]`. Derived, it reads `tsv.exe` on Windows — disagreeing with the JS mirror (`crates/tsv_wasm/npm/cli.js`), whose hand-written help says `tsv` on every platform, and with the `tsv` bin every consumer invokes. A top-level `--version` switch prints `tsv <version>` (the workspace version) and exits 0. It is top-level only: `main` answers it ahead of argh for the bare argv alone (`cli::is_bare_version`), since argh requires a subcommand — so a bare `tsv` gets argh's own required-subcommand error, and `--version` beside a subcommand reaches `TopLevel::run`, which refuses it (exit 1) rather than silently dropping it. Two commands:

- `tsv parse <file|--content|--stdin> [--pretty] [--parser <type>] [--source-type <script|module>] [--locations]` — emits public JSON AST to stdout: the span-only wire by default (`start`/`end` offsets, no per-node `loc`; Svelte also no `name_loc`) — the wire every binding emits, line/column derivable from source. `--locations` adds `loc` (and Svelte's `name_loc`) through the Rust `loc` emitter — the one product surface that writer has; mirrors acorn's `locations: true`
- `tsv format <paths...|--content|--stdin> [--parser <type>] [--source-type <script|module>] [--check] [--list] [--jobs <n>]` — formats paths in place (writes only when output differs); `--content`/`--stdin` print to stdout. `--list` prints the discovered in-scope files without formatting (path mode only; mutually exclusive with `--check`, and refuses `--jobs` as `--content` does; empty scope exits 0); `--source-type` applies to `--content`/`--stdin` only (path mode resolves the source type per file: the module grammar retried as a script, or the module grammar alone where the extension settles it — see [docs/cli.md §Multi-File Formatting](../../docs/cli.md#multi-file-formatting))

**Library (`tsv_cli::cli`, `tsv_cli::json_utils`)** — re-exported via `lib.rs` for `tsv_debug`'s commands. The stable items:

- `cli::input::{Input, InputArgs, ResolvedInput, ParserType, parse_source_type_arg, check_source_type_language}` — unified file / `--content` / `--stdin` plumbing + extension auto-detect; `ParserType::name()` is the canonical lowercase name (`--parser` values, sidecar tool keys); `InputArgs::resolve_with_source_type` is the one statement of the single-input ladder both commands run, over the two checks it composes: the `--source-type` spelling, the parser, whether the language has a goal axis, and only then the read (so a `--stdin` refusal never waits on its writer)
- `cli::format_source::{format_source, format_source_with_source_type}()` — the in-process parse+format entry point keyed by `ParserType`; the single definition of "format with tsv". The shared implementation is the crate-private `format_source_in(source, parser_type, goal: Option<Goal>, &Bump, &DocArena)`, which calls each language's `format_in` with the AST bump-allocated into the caller's `Bump` and the doc IR into the caller's `DocArena` (nothing borrowed escapes). A `None` goal is not `Goal::Module` but *no source type named* — the module grammar retried as a script if that parse fails, so every goal-less caller (every `tsv_debug` audit) formats a legacy sloppy script. `format_source` is the single-shot wrapper (a fresh source-pre-sized `Bump` + `DocArena` per call), used by `tsv_debug` (`compare`, `ast_diff`, fixture validation) and the `--content`/`--stdin` path. The `format` command's parallel workers call `format_source_in` directly, each reusing one `Bump` **and one `DocArena`** (both `reset()` between files) and passing the goal the file's own extension settles (`tsv_ts::Goal::from_extension` — `.mjs`/`.mts` are modules by name and take no script retry)
- `cli::discover::discover_files()` — file/dir expansion with the formattable-extension filter and gitignore-aware ignore evaluation via `tsv_ignore::IgnoreStack` (full two-regime rules: [root CLAUDE.md §Configuration](../../CLAUDE.md#configuration)). Returns `Discovered { files, diagnostics }` — the sorted, deduplicated files plus the walk's `Diagnostics { errors, warnings, all_arguments_excluded }` (`errors` non-fatal traversal errors; `warnings` stderr-only, e.g. the heuristic-shadow no-op, touching neither exit code nor stdout; `all_arguments_excluded` whether every argument was a named file an ignore rule excluded, the run that exits 0 rather than `No files to format`), `Err` per unresolvable arg. The FS walk + format-root resolution + ignore-file reading live here; the **pure per-entry verdict** — safety nets, the build-output heuristic + its shadow-warning text, the formattable-extension check — is delegated to `tsv_discover` (`classify_dir`/`should_format_file`), shared with the WASM CLI and the VS Code extension so all three agree by construction
- `cli::discover::discover_into()` + `cli::discover::FileSink` — the same walk (same scope rules, same file set) handing each file to a sink as it's found instead of returning a set, returning `Diagnostics { errors, warnings, all_arguments_excluded }`. **Nothing orders or deduplicates**: files arrive in walk order and the caller owns any ordering. Two obligations, both documented on the function: report in sorted-path order anyway, and **stream only a single root** (overlapping roots can yield a file twice, and the dedup that removes it needs the whole set). `discover_files` is this plus the sort and the two dedups
- `cli::pool::{spawn_pool, join_pool, drain, slot_outcomes, FileQueue, QueueSink, ReleasePoolOnUnwind, default_jobs}` — **crate-private** (a private module, `pub(crate)` items; not part of the `tsv_debug` surface): the worker pool behind `format`'s two path-mode routes — its default width, bring-up and teardown, the hand-off a streaming walk feeds it through, the claim loop every worker runs, and the read-out that puts each claimed outcome back at its index. What a file's outcome *is* stays with the command (`commands/format.rs`, whose `WorkerArenas` is the work a claim hands to `drain`).
- `cli::stack::{STACK_SIZE, sized_thread, run_on_sized_stack, MAX_WORKERS_PER_LOGICAL_CPU, clamp_worker_count}` — how big every tsv work thread is, how to get onto one, and how many tsv will ask the OS for. `sized_thread(name)` builds a named, sized `thread::Builder`; `run_on_sized_stack(f)` runs `f` on one and returns its value (a panic propagates as exit 101; a refused spawn falls back to this thread) — `tsv_debug`'s `main` uses it for the same reason `tsv`'s does. `clamp_worker_count` holds an explicit `--jobs` to `4 × logical` CPUs (announced on stderr when it bites), shared with `tsv_debug`'s audit pool so the two `--jobs` flags cannot drift
- `cli::out::{write_stdout, write_stderr, exit_with_error, exit_with_parse_error, path_bytes, path_text}` + the `out_line!` / `err_line!` macros over them — the one place the CLI writes to either fd (`#![deny(clippy::print_stdout, clippy::print_stderr)]` at both crate roots makes a stray print macro fail clippy — `deno task lint`, part of `check`). `println!`/`eprintln!` **panic** when their write fails, and a consumer that exits early (`| head`) fails it by construction, so every byte goes through here: a `BrokenPipe` write stops quietly and the run finishes on its own terms; a `WouldBlock` one (a non-blocking description the process shares with a parent — a Node task runner that opens its own piped `process.stdout` while `tsv` runs flips it under the child) is waited out with a backoff capped at a millisecond, partial writes honored; any other error, a zero-length write included, still panics. **Paths**: `path_bytes` is how a path reaches stdout — its own bytes on unix, since the changed-path report and `--list` are for scripting over and `Path::display`'s U+FFFD spelling of a non-UTF-8 name names nothing on disk; `path_text` is how one reaches a stderr diagnostic, `display`'s lossy spelling. Both apply the one quoting rule every printed path takes, `tsv_discover::quote_path`: a name holding a control character or a double quote is C-quoted as `git ls-files` prints it, so a diagnostic stays one line and a listing line beginning with `"` is a quoted one (the warnings `tsv_discover` builds arrive quoted already). **Exits**: `exit_with_error(code, message)` is the shape every argument refusal takes, mirrored by `cli.js`'s function of the same name; `exit_with_parse_error(code, &error)` is the single-input engine failure (`parse`, `format --content`/`--stdin`) — `Parse error:` for a located `ParseError`, `Error:` for the positionless kinds that are not parse errors (the size cap, a format refusal); `cli.js`'s `single_input_failure` splits the same two on the facade's `SyntaxError`. The quoting rule, and why a closed reader is quiet rather than 141 or a restored `SIGPIPE`: [docs/cli.md §Multi-File Formatting](../../docs/cli.md#multi-file-formatting)
- `json_utils::indent_json_with_tabs()` — the `--pretty` re-indenter: the tab-indented form of a compact JSON document, produced by a linear byte walk with no deserializer (so no depth ceiling of its own — see [docs/cli.md §Recursion Depth](../../docs/cli.md#recursion-depth)). Byte-identical to serializing the parsed tree with `serde_json`'s tab `PrettyFormatter`, which is what `tsv_debug::json::to_json_with_tabs` does for the `Value`s the fixture pipeline holds; the equivalence is pinned over every fixture input by a test beside that function

## Distinctives

- **argh for arg parsing.** Each command is a `FromArgs` struct under `cli/commands/`; `cli::TopLevel`/`Subcommand` is the dispatch enum. argh has no struct-flattening attribute, so the shared input fields (`--content`, `--stdin`, `--parser`, file path) are declared per command and assembled into `cli::input::InputArgs` for resolution.
- **Three input modes per command** — file path(s), `--content <str>` (requires explicit `--parser`), `--stdin` (requires explicit `--parser`). `parse` accepts `--parser` on a file path as an override; `format` rejects it (paths always trust the extension). `--content` is preferred for agents; `--stdin` works but is discouraged.
- **`format` is multi-file and parallel.** Positional args accept files and directories; directories recurse over the JS/TS family (`.ts`/`.mts`/`.cts`/`.js`/`.mjs`/`.cjs`, all parsed as TypeScript), `.svelte`, and `.css` — every extension read without regard to ASCII case, as prettier infers a parser from the lowercased name — with gitignore-aware discovery (`cli/discover.rs`): safety nets always pruned, a cwd-independent **format root** (repo root in a git tree, else the filesystem root), and `.gitignore`/`.formatignore`/`.prettierignore` honored per the [two-regime rules](../../CLAUDE.md#configuration). Because the format root is cwd-independent, a target directory formats the same however its path is spelled and wherever tsv runs.
  - **A named path is bounded by the ignore files alone** — the safety nets and the build-output heuristic grade no named path. It is graded where it was typed (`absolute_named_path`: the parent canonicalized, the name kept, so a symlink argument is bounded at its own path as git and prettier read it, not at its target) and, for a symlink, as the link it is (`classify_args` reads `symlink_metadata` beside `metadata`; a directory-only rule does not match a symlinked directory argument, and one a rule does exclude counts as an excluded *file* argument). A file or directory argument a rule excludes, through an ancestor or at itself, is skipped, with the warning `tsv_discover::excluded_argument_warning` calls for (none for a file a `.formatignore`/`.prettierignore` rule excludes, whatever a `.gitignore` says); a run whose every argument was an excluded file exits 0 rather than failing with nothing to format. File arguments share one ignore scope, moved from each one's directory to the next's (`FileScope`), and no ignore file inside a directory a rule excludes is read for a named path (`push_dir_layers`, whose gate is all it adds to `push_layers` — the one statement of the layer ladder, which the descent runs too, so a preloaded ancestor and a walked directory read the same files).
  - **A file argument is held to the extension check first** — the parser dispatch behind a path has no unknown arm, so an unsupported extension would be parsed as TypeScript (a `.json` file can even format *successfully* into invalid JSON).
  - Args that don't resolve, and file args tsv doesn't format, fail the run upfront (all reported, nothing written); traversal errors below a valid root report and continue. With multiple roots, overlapping spellings of the same file dedupe by canonical path (skipped for a single root — symlinks aren't followed, so no duplicates are possible). Per-file errors (and panics, via `catch_unwind` — effective in dev/corpus profiles only since release uses `panic = "abort"`) report and continue.
- **Two ways files reach the pool, one reporting order.** A **single directory root** — the common invocation — *streams*: `discover_into` hands each file to a `FileSink` as the walk finds it, so the walk runs beside the first files' parse+format instead of in front of an idle pool. Every other shape (explicit file arguments, multiple roots) collects the whole set first, because the canonical-path dedup is set-wide. Both are std-only (no rayon) and both report **in sorted-path order regardless of completion order** — streaming takes each path's sort key on the way past and orders the results at the end, so *work* order may differ from *report* order but the output cannot. Two properties of the streaming queue are load-bearing and measured, not incidental:
  - **Wake exactly as many workers as there is new work for** (`min(waiting, added)`, `notify_one`). A `notify_all` is correct but pathological when the *walk* is the bottleneck — a large tree with a small in-scope set, where discovery can be 40–67% of the run — because the pool is then starved, every batch finds all N workers parked, and the surplus wakeups land on the producer's critical path.
  - **A worker takes the `PathBuf` out of its slot and hands it back with the outcome**, so the lock is held for a pointer swap and no path is ever copied.
- **The default worker count is `min(logical, ceil(1.5 × physical))`, not `available_parallelism()`; an explicit `--jobs` is held to `4 × logical` CPUs; a spawn the OS refuses narrows the pool.** The why of each — SMT non-scaling, the walk-bound cost of one worker per logical CPU, the SMT probe, the blast-radius (`TasksMax`) ceiling, the narrowing warning — is [docs/cli.md §Multi-File Formatting](../../docs/cli.md#multi-file-formatting)'s parallelism note. Crate-side: `--jobs` is clamped to the file count and floored at 1 (`--jobs 0` means `--jobs 1`), and **both discovery paths clamp**, which is load-bearing: `format_streamed` can't clamp to the file count (it doesn't know it yet, which is the point of streaming) but must still floor at 1, or a zero-width pool leaves every file unclaimed and each reads out through the died-outside-`catch_unwind` arm as a bogus "worker thread panicked" — a run that formats nothing and blames a worker that never existed. The `4 ×` ceiling lives in `cli::stack::clamp_worker_count` because `tsv_debug`'s audit pool takes it from the same function. `spawn_pool` takes however many threads it is given, warns (`only N of M format workers started`) and lets the claim-by-index queue redistribute the work; when not one thread starts, the calling thread formats (`join_pool` runs the one `drain` loop there — both discovery paths spawn and join through those two functions, so the worker and that fallback can't drift). A refused spawn must not reach an `expect`: that makes `--jobs` the one argument answering with a panic rather than exit 2, and on the streamed path the panic unwinds past `FileQueue::finish` and leaves the already-parked workers to be joined by a `thread::scope` that waits forever, so the process hangs holding the pool's stacks instead of dying. `ReleasePoolOnUnwind` releases the pool on any other unwind through the producer.
- **One stack reservation, every route** (`cli/stack.rs`). `main` runs the whole subcommand on a thread with `STACK_SIZE` reserved and the format workers reserve the same, so nesting depth is bounded by tsv rather than by which route the caller took: inherited, the main thread's stack is the process `RLIMIT_STACK` on Unix but **1 MiB on Windows**, while a spawned thread takes Rust's 2 MiB — an 8x depth difference between `tsv format <path>` and `tsv format --content` on one machine, with `tsv parse` (no pool) on the low side. It is decided at all because a stack overflow is **not** a catchable panic: the `catch_unwind` above cannot turn it into a per-file error under any profile — it aborts, and a directory sweep that aborts has already rewritten files it never got to report. A reservation, not a commitment — pages commit lazily, so it costs address space and ~0 RSS, and spawn+join measures ~31 µs, flat from 2 MiB to 32 MiB (past ~40 MiB glibc stops caching thread stacks and the spawn cost rises). `stack::sized_thread(name)` is the single constructor every `thread::Builder` spawn in `tsv_cli` goes through, so a future thread cannot quietly miss the reservation (the one deliberate opt-out is `tsv_debug`'s experimental tsc-conformance runner, whose sweep thread reserves a far larger 512 MiB with a watchdog beside it) — and it **names** the thread (`tsv`, `tsv-format`), because the runtime's `thread '<name>' has overflowed its stack` line is the only diagnostic an uncatchable abort leaves, and an unnamed thread prints `<unknown>` there. `tsv_debug` takes it at all three of its levels, since its commands drive the same recursion over whole corpora, where an overflow kills the sweep rather than reporting one file: `main` runs on the same wrapper, its injection-audit pool builds its workers with `sized_thread`, and both its tokio runtimes — the shared one its async commands run on, and the Deno sidecar's, which reads the canonical AST back with no recursion limit — are built with `STACK_SIZE` (its async commands run tsv's own parser and printer inside `buffer_unordered` bodies, so tokio's 2 MiB default would be a route ~16x shallower than every other). Depth numbers and the binding surfaces' own ceilings: [docs/cli.md §Recursion Depth](../../docs/cli.md#recursion-depth).
- **`format` exit codes: 0 clean, 1 would-change (`--check`), 2 errors.** Changed paths go to stdout (greppable), errors and the summary line to stderr. `--check` also works with `--content`/`--stdin` (exit code only, nothing on stdout); `--jobs` is path-mode only and errors otherwise. Other commands keep 0/1 — `parse` answers an argument error (a missing `--parser`, a bad `--source-type`, an unsupported extension, a directory named as the file — refused by name in `InputArgs::parser_type`, ahead of the extension check and a `--parser` override, in wording neutral enough for the `tsv_debug` commands that resolve through it) with the same 1 as a parse failure, a deliberate narrower dialect than `format`'s 2 (its callers read the wire or nothing, so the split buys them no branch), mirrored code for code by `cli.js`. **A closed consumer touches none of them**: `| head` stops the write and the run still reports its own verdict (`cli::out`, whose bullet above links the why).
- **`--pretty` is `parse`-only, and it never reads the wire back.** Compact JSON is the default to keep agent/CI output greppable; pretty mode re-indents the compact bytes with tabs (`json_utils::indent_json_with_tabs`, not serde's 2-space default) in one linear pass. It must not read the wire back into a `serde_json::Value`: serde_json's default recursion limit of 128 refuses a wire past ~60 nested arrays or ~40 nested objects that the compact route just emitted — a ceiling 400× below the parser's and below every oracle's ([docs/cli.md §Recursion Depth](../../docs/cli.md#recursion-depth)). The linear pass stops exactly where the parser stops.
- **Convert features are mandatory.** `tsv_*` deps are declared with `features = ["convert", "locations"]` because `parse` always goes through the convert layer (`convert_ast_json_bytes`, or `convert_ast_json_bytes_with_locations` under `--locations`, written to stdout as bytes for compact output — skipping output UTF-8 validation — and re-indented for `--pretty`); the internal AST is never serialized.
- **Shared with `tsv_debug`.** `tsv_debug` commands import `tsv_cli::cli::input`, `tsv_cli::cli::format_source`, `tsv_cli::cli::stack`, and (the fixture gate) `tsv_cli::json_utils`. Treat `pub` items in those modules as a contract — moving or renaming them ripples through dozens of `tsv_debug` source files.
