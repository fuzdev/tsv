# tsv_cli

> Production CLI for `tsv` — pure Rust, no Deno

Ships the `tsv` binary (defined in `Cargo.toml` `[[bin]]`). Depends on `tsv_ts`, `tsv_css`, and `tsv_svelte` (each with `convert` features), `tsv_lang` (the `estimated_ast_arena_capacity` parse-arena pre-size), `tsv_ignore` (discovery ignore-file matching) and `tsv_discover` (the per-directory prune/descend policy over it), plus `argh`, `serde`, `serde_json`, and `bumpalo` (the parse arena) — nothing else. `tsv_debug` depends on this crate and reuses its `cli::` library surface for its own command set; keep that surface stable.

For end-user invocation syntax see the [root CLAUDE.md §CLI Usage](../../CLAUDE.md#cli-usage---parse--format). For pattern background see [`docs/cli.md`](../../docs/cli.md).

## Public API

**Binary (`tsv`)** — `main.rs` parses `cli::TopLevel` from argv and dispatches. It spells out `argh::from_env`'s body (same early-exit contract: `--help` to stdout with exit 0, a parse error to stderr with exit 1) for one reason: the command name argh prints in usage/help/error text is **pinned to `tsv`** rather than derived from `argv[0]`. Derived, it reads `tsv.exe` on Windows — disagreeing with the JS mirror (`crates/tsv_wasm/npm/cli.js`), whose hand-written help spells the same contract as `tsv` on every platform, and with the `tsv` bin every consumer actually invokes. A top-level `--version` switch prints `tsv <version>` (the workspace version) and exits 0 — top-level only, and the subcommand field is `Option` solely so it can parse: a bare `tsv` reproduces argh's required-subcommand error verbatim (see `TopLevel::run`). Two commands:

- `tsv parse <file|--content|--stdin> [--pretty] [--parser <type>] [--goal <script|module>] [--no-locations]` — emits public JSON AST to stdout. `--no-locations` emits the span-only wire (drops per-node `loc`; Svelte also `name_loc`; no-op for CSS) — offsets only, line/column derivable from source; mirrors acorn's `locations: false`
- `tsv format <paths...|--content|--stdin> [--parser <type>] [--goal <script|module>] [--check] [--list] [--jobs <n>]` — formats paths in place (writes only when output differs); `--content`/`--stdin` print to stdout. `--list` prints the discovered in-scope files without formatting (path mode only; mutually exclusive with `--check`; empty scope exits 0); `--goal` applies to `--content`/`--stdin` only (file paths are formatted as modules)

**Library (`tsv_cli::cli`, `tsv_cli::json_utils`)** — re-exported via `lib.rs` for `tsv_debug` to build its own commands on the same plumbing. The stable items:

- `cli::input::{Input, InputArgs, ParserType}` — unified file / `--content` / `--stdin` plumbing + extension auto-detect; `ParserType::name()` is the canonical lowercase name (`--parser` values, sidecar tool keys)
- `cli::format_source::{format_source, format_source_in, format_source_with_goal, format_source_in_with_goal}()` — the in-process parse+format entry point keyed by `ParserType`; the single definition of "format with tsv". `format_source_in_with_goal(source, parser_type, goal, &Bump, &DocArena)` is the shared implementation (`format_source_in` is its `Goal::Module` form) (the AST is bump-allocated into the caller's `Bump` and the doc IR into the caller's `DocArena`, nothing borrowed escapes — it calls each language's `format_in`); `format_source` is the single-shot wrapper that allocates a fresh source-pre-sized `Bump` + `DocArena` per call. The `format` command's parallel workers call `format_source_in` so each worker reuses one `Bump` **and one `DocArena`** (both `reset()` between files); `tsv_debug` (`compare`, `ast_diff`, fixture validation) and the `--content`/`--stdin` path use `format_source`
- `cli::discover::discover_files()` — file/dir expansion with the formattable-extension filter and gitignore-aware ignore evaluation via `tsv_ignore::IgnoreStack` (full two-regime rules: [root CLAUDE.md §Configuration](../../CLAUDE.md#configuration)). Returns `Discovered { files, errors, warnings }` (non-fatal traversal errors; `warnings` are stderr-only diagnostics — e.g. the heuristic-shadow no-op — that don't touch the exit code or stdout), `Err` per unresolvable arg. The FS walk + format-root resolution + ignore-file reading live here; the **pure per-entry verdict** — safety nets, the build-output heuristic + its shadow-warning text, the formattable-extension check — is delegated to `tsv_discover` (`classify_dir`/`should_format_file`), shared with the WASM CLI and the VS Code extension so all three agree by construction
- `cli::discover::discover_into()` + `cli::discover::FileSink` — the same walk with the files handed to a sink as they're found instead of returned as a set, returning `Diagnostics { errors, warnings }`. Same scope rules, same file set; the difference is that **nothing orders or deduplicates** — files arrive in walk order and the caller owns whatever ordering it needs. Two obligations come with it, both documented on the function: report in sorted-path order anyway, and **stream only a single root** (overlapping roots can yield a file twice, and the dedup that removes it needs the whole set). `discover_files` is this plus the sort and the two dedups
- `cli::stack::{STACK_SIZE, sized_thread, run_on_sized_stack, MAX_WORKERS_PER_LOGICAL_CPU, clamp_worker_count}` — how big every tsv work thread is, how to get onto one, and how many of them tsv will ask the OS for. `clamp_worker_count` holds an explicit `--jobs` to `4 × logical` CPUs (announced on stderr when it bites) and is shared with `tsv_debug`'s audit pool, so the two `--jobs` flags cannot drift. The reservation and the two ways onto it: `sized_thread(name)` builds a named, sized `thread::Builder`, `run_on_sized_stack(f)` runs `f` on one and returns its value (propagating a panic as exit 101, falling back to this thread if the spawn is refused). `tsv_debug`'s `main` uses the wrapper for the same reason `tsv`'s does
- `json_utils::to_json_with_tabs()` — tab-indented `serde_json` (matches workspace style)

## Distinctives

- **argh for arg parsing.** Each command is a `FromArgs` struct under `cli/commands/`; `cli::TopLevel`/`Subcommand` is the dispatch enum. argh has no struct-flattening attribute, so the shared input fields (`--content`, `--stdin`, `--parser`, file path) are declared per command and assembled into `cli::input::InputArgs` for resolution.
- **Three input modes per command** — file path(s), `--content <str>` (requires explicit `--parser`), `--stdin` (requires explicit `--parser`). `parse` accepts `--parser` on a file path as an override; `format` rejects it (paths always trust the extension). The "preferred for agents" path is `--content`; `--stdin` is supported but discouraged.
- **`format` is multi-file and parallel.** Positional args accept files and directories; directories recurse over the JS/TS family (`.ts`/`.mts`/`.cts`/`.js`/`.mjs`/`.cjs`, all parsed as TypeScript), `.svelte`, and `.css` with gitignore-aware discovery (`cli/discover.rs`) — safety nets always pruned, a cwd-independent **format root** (repo root in a git tree, else the filesystem root), and `.gitignore`/`.formatignore`/`.prettierignore` honored per the [two-regime rules](../../CLAUDE.md#configuration); an **explicit file argument bypasses the ignore files** (they govern discovery, and the caller named that file) but **not the extension check** (the parser dispatch behind a path has no unknown arm, so an unsupported extension would be parsed as TypeScript — a `.json` file can even format *successfully* into invalid JSON). Because the format root is cwd-independent, a target directory formats the same however its path is spelled, wherever tsv runs, and whether targeted directly or via an ancestor. Args that don't resolve, and file args tsv doesn't format, fail the run upfront (all reported, nothing written); traversal errors below a valid root report and continue. With multiple roots, overlapping spellings of the same file dedupe by canonical path (skipped for a single root — symlinks aren't followed, so no duplicates are possible). Per-file errors (and panics, via `catch_unwind` — effective in dev/corpus profiles only since release uses `panic = "abort"`) report and continue.

**Two ways files reach the pool, one reporting order.** A **single directory root** — the common invocation — *streams*: `discover_into` hands each file to a `FileSink` as the walk finds it, so the walk runs beside the first files' parse+format instead of in front of an idle pool. Every other shape (explicit file arguments, multiple roots) collects the whole set first, because the canonical-path dedup is set-wide. Both are std-only (no rayon) and both report **in sorted-path order regardless of completion order** — streaming takes each path's sort key on the way past and orders the results at the end, so *work* order may differ from *report* order but the output cannot. Two properties of the streaming queue are load-bearing and measured, not incidental:

- **Wake exactly as many workers as there is new work for** (`min(waiting, added)`, `notify_one`). A `notify_all` is correct but pathological when the *walk* is the bottleneck — a large tree with a small in-scope set, where discovery can be 40–67% of the run — because the pool is then starved, every batch finds all N workers parked, and the surplus wakeups land on the producer's critical path.
- **A worker takes the `PathBuf` out of its slot and hands it back with the outcome**, so the lock is held for a pointer swap and no path is ever copied.
- **The default worker count is `min(logical, ceil(1.5 × physical))`, not `available_parallelism()`.** This workload does not scale onto SMT siblings (memory-bound per-file work), and on a large tree the streaming producer is the bottleneck, so surplus workers compete with the walk thread for cores — one worker per logical CPU costs up to 28% there and buys nothing on flat repos. SMT width is one read of `/sys/devices/system/cpu/cpu0/topology/thread_siblings_list`; unreadable or no SMT ⇒ the cap is inert and the logical count stands, so the rule can only lower the worker count, never raise it. `--jobs` overrides, clamped to the file count and floored at 1 — `--jobs 0` is a width, not an opt-out, and means `--jobs 1`. **Both discovery paths clamp**, which is load-bearing: `format_streamed` can't clamp to the file count (it doesn't know it yet, which is the point of streaming) but must still floor at 1, or a zero-width pool leaves every file unclaimed and each reads out through the died-outside-`catch_unwind` arm as a bogus "worker thread panicked" — a run that formats nothing and blames a worker that never existed. **An explicit `--jobs` is also held to `4 × logical` CPUs** (`cli::stack::clamp_worker_count`, warned when it bites — stated there, not here, because `tsv_debug`'s audit pool takes the same ceiling from the same function) — not a throughput number (the default is already *below* logical) but a blast-radius one: each worker reserves `STACK_SIZE` of address space, and an unbounded count walks up to the OS's refusal, which on a systemd machine means the login session's whole `TasksMax` and wedges every other process on it. **Past that, the ceiling is the OS's answer, not an error**: `spawn_pool` takes however many threads it is given, warns (`only N of M format workers started`) and lets the claim-by-index queue redistribute the work — and when not one thread starts, the calling thread formats (`drain_queue` / `drain_indexed` are functions precisely so the worker and that fallback can't drift). A refused spawn used to reach an `expect`, which made `--jobs` the one argument that answered with a panic rather than exit 2; on the streamed path that panic unwound past `FileQueue::finish` and left the already-parked workers to be joined by a `thread::scope` that would wait forever, so the process hung holding the pool's stacks instead of dying. `ReleasePoolOnUnwind` now closes that gap for any other unwind through the producer.
- **One stack reservation, every route** (`cli/stack.rs`). `main` runs the whole subcommand on a thread with `STACK_SIZE` reserved and the format workers reserve the same, so nesting depth is bounded by tsv rather than by which route the caller took: inherited, the main thread's stack is the process `RLIMIT_STACK` on Unix but **1 MiB on Windows** (the linker writes it into the executable header; nothing at run time raises it), while a spawned thread takes Rust's 2 MiB — an 8x depth difference between `tsv format <path>` and `tsv format --content` on one machine, with `tsv parse` (no pool, and a second recursion in the wire-JSON writer) on the low side. This is a reservation, not a commitment — pages commit lazily, so it costs address space and ~0 RSS, and spawn+join measures ~31 µs, flat from 2 MiB to 32 MiB (past ~40 MiB glibc stops caching thread stacks and the spawn cost rises). Why it has to be decided at all: a stack overflow is **not** a catchable panic, so the `catch_unwind` above cannot turn it into a per-file error under any profile — it aborts, and a directory sweep that aborts has already rewritten files it never got to report. `stack::sized_thread(name)` is the single constructor every `thread::Builder` spawn goes through, so a future thread cannot quietly miss the reservation by building its own — and it **names** the thread (`tsv`, `tsv-format`), because the runtime's `thread '<name>' has overflowed its stack` line is the only diagnostic an uncatchable abort leaves and an unnamed thread prints `<unknown>` there. `tsv_debug` takes it at all three of its levels: `main` runs on the same wrapper, its injection-audit pool builds its workers with `sized_thread`, and its shared tokio runtime is built with `STACK_SIZE` (its async commands run tsv's own parser and printer inside `buffer_unordered` bodies, so tokio's 2 MiB default would be a route ~16x shallower than every other) — those commands drive the same recursion over whole corpora, where an overflow kills the sweep rather than reporting one file. Depth numbers and the binding surfaces' own ceilings: [docs/cli.md §Recursion Depth](../../docs/cli.md#recursion-depth).
- **`format` exit codes: 0 clean, 1 would-change (`--check`), 2 errors.** Changed paths go to stdout (greppable), errors and the summary line to stderr. `--check` also works with `--content`/`--stdin` (exit code only, nothing on stdout); `--jobs` is path-mode only and errors otherwise. Other commands keep 0/1.
- **`--pretty` is `parse`-only.** Compact JSON is the default to keep agent/CI output greppable; pretty mode uses `to_json_with_tabs` (not serde's 2-space default) so output matches workspace formatting.
- **Convert features are mandatory.** `tsv_*` deps are declared with `features = ["convert"]` because `parse` always goes through the convert layer (`convert_ast_json_bytes` for compact output — written to stdout as bytes, skipping output UTF-8 validation — `convert_ast_json` for `--pretty`); the internal AST is never serialized.
- **Shared with `tsv_debug`.** `tsv_debug` commands import `tsv_cli::cli::input`, `tsv_cli::cli::format_source`, `tsv_cli::cli::stack`, and `tsv_cli::json_utils`. Treat `pub` items in those modules as a contract — moving or renaming them ripples through ~45 `tsv_debug` source files.
