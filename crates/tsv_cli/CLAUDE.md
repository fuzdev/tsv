# tsv_cli

> Production CLI for `tsv` — pure Rust, no Deno

Ships the `tsv` binary (defined in `Cargo.toml` `[[bin]]`). Depends on `tsv_ts`, `tsv_css`, and `tsv_svelte` (each with `convert` features), `tsv_lang` (the `estimated_ast_arena_capacity` parse-arena pre-size), `tsv_ignore` (discovery ignore-file matching) and `tsv_discover` (the per-directory prune/descend policy over it), plus `argh`, `serde`, and `serde_json` — nothing else. `tsv_debug` depends on this crate and reuses its `cli::` library surface for its own command set; keep that surface stable.

For end-user invocation syntax see the [root CLAUDE.md §CLI Usage](../../CLAUDE.md#cli-usage---parse--format). For pattern background see [`docs/cli.md`](../../docs/cli.md).

## Public API

**Binary (`tsv`)** — `main.rs` parses `cli::TopLevel` via `argh::from_env()` and dispatches. A top-level `--version` switch prints `tsv <version>` (the workspace version) and exits 0 — top-level only, and the subcommand field is `Option` solely so it can parse: a bare `tsv` reproduces argh's required-subcommand error verbatim (see `TopLevel::run`). Two commands:

- `tsv parse <file|--content|--stdin> [--pretty] [--parser <type>] [--goal <script|module>] [--no-locations]` — emits public JSON AST to stdout. `--no-locations` emits the span-only wire (drops per-node `loc`; Svelte also `name_loc`; no-op for CSS) — offsets only, line/column derivable from source; mirrors acorn's `locations: false`
- `tsv format <paths...|--content|--stdin> [--parser <type>] [--check] [--list] [--jobs <n>]` — formats paths in place (writes only when output differs); `--content`/`--stdin` print to stdout. `--list` prints the discovered in-scope files without formatting (path mode only; mutually exclusive with `--check`; empty scope exits 0)

**Library (`tsv_cli::cli`, `tsv_cli::json_utils`)** — re-exported via `lib.rs` for `tsv_debug` to build its own commands on the same plumbing. The stable items:

- `cli::input::{Input, InputArgs, ParserType}` — unified file / `--content` / `--stdin` plumbing + extension auto-detect; `ParserType::name()` is the canonical lowercase name (`--parser` values, sidecar tool keys)
- `cli::format_source::{format_source, format_source_in}()` — the in-process parse+format entry point keyed by `ParserType`; the single definition of "format with tsv". `format_source_in(source, parser_type, &Bump, &DocArena)` is the shared implementation (the AST is bump-allocated into the caller's `Bump` and the doc IR into the caller's `DocArena`, nothing borrowed escapes — it calls each language's `format_in`); `format_source` is the single-shot wrapper that allocates a fresh source-pre-sized `Bump` + `DocArena` per call. The `format` command's parallel workers call `format_source_in` so each worker reuses one `Bump` **and one `DocArena`** (both `reset()` between files); `tsv_debug` (`compare`, `ast_diff`, fixture validation) and the `--content`/`--stdin` path use `format_source`
- `cli::discover::discover_files()` — file/dir expansion with the formattable-extension filter and gitignore-aware ignore evaluation via `tsv_ignore::IgnoreStack` (full two-regime rules: [root CLAUDE.md §Configuration](../../CLAUDE.md#configuration)). Returns `Discovered { files, errors, warnings }` (non-fatal traversal errors; `warnings` are stderr-only diagnostics — e.g. the heuristic-shadow no-op — that don't touch the exit code or stdout), `Err` per unresolvable arg. The FS walk + format-root resolution + ignore-file reading live here; the **pure per-entry verdict** — safety nets, the build-output heuristic + its shadow-warning text, the formattable-extension check — is delegated to `tsv_discover` (`classify_dir`/`should_format_file`), shared with the WASM CLI and the VS Code extension so all three agree by construction
- `cli::discover::discover_into()` + `cli::discover::FileSink` — the same walk with the files handed to a sink as they're found instead of returned as a set, returning `Diagnostics { errors, warnings }`. Same scope rules, same file set; the difference is that **nothing orders or deduplicates** — files arrive in walk order and the caller owns whatever ordering it needs. Two obligations come with it, both documented on the function: report in sorted-path order anyway, and **stream only a single root** (overlapping roots can yield a file twice, and the dedup that removes it needs the whole set). `discover_files` is this plus the sort and the two dedups
- `json_utils::to_json_with_tabs()` — tab-indented `serde_json` (matches workspace style)

## Distinctives

- **argh for arg parsing.** Each command is a `FromArgs` struct under `cli/commands/`; `cli::TopLevel`/`Subcommand` is the dispatch enum. argh has no struct-flattening attribute, so the shared input fields (`--content`, `--stdin`, `--parser`, file path) are declared per command and assembled into `cli::input::InputArgs` for resolution.
- **Three input modes per command** — file path(s), `--content <str>` (requires explicit `--parser`), `--stdin` (requires explicit `--parser`). `parse` accepts `--parser` on a file path as an override; `format` rejects it (paths always trust the extension). The "preferred for agents" path is `--content`; `--stdin` is supported but discouraged.
- **`format` is multi-file and parallel.** Positional args accept files and directories; directories recurse over the JS/TS family (`.ts`/`.mts`/`.cts`/`.js`/`.mjs`/`.cjs`, all parsed as TypeScript), `.svelte`, and `.css` with gitignore-aware discovery (`cli/discover.rs`) — safety nets always pruned, a cwd-independent **format root** (repo root in a git tree, else the filesystem root), and `.gitignore`/`.formatignore`/`.prettierignore` honored per the [two-regime rules](../../CLAUDE.md#configuration); an **explicit file argument bypasses the ignore files** (they govern discovery, and the caller named that file) but **not the extension check** (the parser dispatch behind a path has no unknown arm, so an unsupported extension would be parsed as TypeScript — a `.json` file can even format *successfully* into invalid JSON). Because the format root is cwd-independent, a target directory formats the same however its path is spelled, wherever tsv runs, and whether targeted directly or via an ancestor. Args that don't resolve, and file args tsv doesn't format, fail the run upfront (all reported, nothing written); traversal errors below a valid root report and continue. With multiple roots, overlapping spellings of the same file dedupe by canonical path (skipped for a single root — symlinks aren't followed, so no duplicates are possible). Per-file errors (and panics, via `catch_unwind` — effective in dev/corpus profiles only since release uses `panic = "abort"`) report and continue.

**Two ways files reach the pool, one reporting order.** A **single directory root** — the common invocation — *streams*: `discover_into` hands each file to a `FileSink` as the walk finds it, so the walk runs beside the first files' parse+format instead of in front of an idle pool. Every other shape (explicit file arguments, multiple roots) collects the whole set first, because the canonical-path dedup is set-wide. Both are std-only (no rayon) and both report **in sorted-path order regardless of completion order** — streaming takes each path's sort key on the way past and orders the results at the end, so *work* order may differ from *report* order but the output cannot. Two properties of the streaming queue are load-bearing and measured, not incidental:

- **Wake exactly as many workers as there is new work for** (`min(waiting, added)`, `notify_one`). A `notify_all` is correct but pathological when the *walk* is the bottleneck — a large tree with a small in-scope set, where discovery can be 40–67% of the run — because the pool is then starved, every batch finds all N workers parked, and the surplus wakeups land on the producer's critical path.
- **A worker takes the `PathBuf` out of its slot and hands it back with the outcome**, so the lock is held for a pointer swap and no path is ever copied.
- **The default worker count is `min(logical, ceil(1.5 × physical))`, not `available_parallelism()`.** This workload does not scale onto SMT siblings (memory-bound per-file work), and on a large tree the streaming producer is the bottleneck, so surplus workers compete with the walk thread for cores — one worker per logical CPU costs up to 28% there and buys nothing on flat repos. SMT width is one read of `/sys/devices/system/cpu/cpu0/topology/thread_siblings_list`; unreadable or no SMT ⇒ the cap is inert and the logical count stands, so the rule can only lower the worker count, never raise it. `--jobs` overrides.
- **`format` exit codes: 0 clean, 1 would-change (`--check`), 2 errors.** Changed paths go to stdout (greppable), errors and the summary line to stderr. `--check` also works with `--content`/`--stdin` (exit code only, nothing on stdout); `--jobs` is path-mode only and errors otherwise. Other commands keep 0/1.
- **`--pretty` is `parse`-only.** Compact JSON is the default to keep agent/CI output greppable; pretty mode uses `to_json_with_tabs` (not serde's 2-space default) so output matches workspace formatting.
- **Convert features are mandatory.** `tsv_*` deps are declared with `features = ["convert"]` because `parse` always goes through the convert layer (`convert_ast_json_bytes` for compact output — written to stdout as bytes, skipping output UTF-8 validation — `convert_ast_json` for `--pretty`); the internal AST is never serialized.
- **Shared with `tsv_debug`.** `tsv_debug` commands import `tsv_cli::cli::input`, `tsv_cli::cli::format_source`, and `tsv_cli::json_utils`. Treat `pub` items in those modules as a contract — moving or renaming them ripples through ~15 debug commands.
