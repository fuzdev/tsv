# tsv_debug

> Developer tooling crate — fixtures, comparisons, corpus runs. Embeds a Deno sidecar for canonical JS tools.

Unlike `tsv_cli` (pure Rust, production binary), `tsv_debug` exists to validate and debug `tsv` against external sources of truth: Prettier (formatting), Svelte's compiler (parsing), acorn-typescript (TS AST shape). The binary `tsv_debug` powers `deno task fixtures:*`, the `deno task *:audit` gates, `deno task audit:corpus`, `deno task idempotency:sweep`, and friends. For the command catalog see [../../CLAUDE.md §Debug Tooling](../../CLAUDE.md#debug-tooling); the audit gates are cataloged in [../../docs/audits.md](../../docs/audits.md), the profiling tools in [../../docs/performance.md](../../docs/performance.md), the Svelte-compiler harnesses in [../../docs/compile_tooling.md](../../docs/compile_tooling.md).

## Architecture Position

Depends on `tsv_ts`, `tsv_css`, `tsv_svelte` (with `convert` features) to drive our parser/formatter, and on `tsv_cli` for shared CLI infrastructure — `tsv_cli::cli::input::{Input, InputArgs, ParserType}`, `tsv_cli::cli::format_source::{format_source, format_source_with_goal}`, `tsv_cli::json_utils::to_json_with_tabs`, and `tsv_cli::cli::stack::run_on_sized_stack` (`main.rs` — this binary drives the same recursive descents over whole corpora, so it takes the same stated stack ceiling the `tsv` binary does) are imported directly rather than reimplemented. The crate is `tokio`-based because the Deno sidecar I/O is async.

The Deno sidecar is a **long-running subprocess pool** spawned lazily on first use and reused across all subsequent calls (`OnceCell<Vec<ActorSlot>>` in `deno/mod.rs`, round-robin dispatch over healable slots). This is orders of magnitude faster than a fresh `deno run` per call — the cost of Prettier/Svelte/acorn module load is paid once per process per `tsv_debug` invocation. The pool defaults to size 1; each sidecar is a single-threaded JS process that handles its queued requests serially (the pool is the only parallelism), so bulk workloads that issue many concurrent calls (`fixtures_validate`, `fixtures_audit`, the `fixtures_update_*` commands, the fixtures integration test) call `deno::init_bulk_pool` before first use — it sizes the pool (via `set_pool_size`/`bulk_pool_size`) and returns a task concurrency to spread the JS work across a few processes (~3 is the measured knee; more just pays extra module loads). Each sidecar runs with `PRETTIER_DEBUG=1` so prettier-plugin-svelte's verbatim-on-error fallback (whole `<script>` block echoed when the embedded formatter throws) surfaces as a tool error instead of fake-stable output. The pool is a process-global `static`, but `tokio::spawn` binds a task to whatever runtime is current at spawn time, so each sidecar's background tasks (actor loop + stdout/stderr readers) and child-process I/O are pinned to a dedicated process-lifetime runtime (`actor::sidecar_runtime`) rather than the caller's — without it a short-lived `#[tokio::test]` runtime that first touched the pool would abort those tasks on exit, and every later test would pull a now-dead actor (`DenoError::ActorShutdown`). The pool also **heals in place**: when a dispatch finds a slot's actor dead (its event loop exited after a crash/timeout), the slot respawns a fresh actor and completes that dispatch on it — safe because a request the old actor's queue never accepted provably never reached a sidecar. A request that was *delivered* and then failed gets a hard error, deliberately without retry, so a flaky oracle stays loud; likewise `run_prettier` returns a hard `DenoError::EmptyOutput` when prettier yields (semantically) empty output for non-empty input — the under-load miss — instead of `Ok("")` that downstream would treat as truth.

## Modules

- `deno/` — Sidecar plumbing: `actor.rs` owns one spawned process (`mod.rs` holds the pool + round-robin dispatch), `protocol.rs` is the JSON-lines wire format, `sidecar.ts` is the embedded TypeScript that runs inside Deno and dispatches to prettier / svelte (parse **and** `compile`) / acorn / parseCss. Pinned npm versions live in `sidecar.ts`. The `svelte-render-key` tool compiles for the server target and reduces the baked template to its browser-visible render (block-aware whitespace collapse, `<script>`/`<style>`/comments stripped) — the authoritative oracle behind the fixture render-equivalence check. ⚠️ Its collapse class is `[ \t\r\n]` (CSS Text 3's document white space characters), **not** `\s` and not `[ \t\r\n\f]`: every character it collapses is one it declares invisible, so a class one character too wide makes the oracle vouch for a formatter that respells that character — with `\f` in the set it reduced `<span>␌<code>a</code>␌</span>` and `<span> <code>a</code> </span>` to the same key, blind to the exact form-feed rewrite the render check exists to catch. `String.prototype.trim` is wider still (it strips NBSP and U+FEFF), so the segment-edge trim is spelled out rather than delegated to it.
- `fixtures/` — The fixture workflow surface — `model.rs` holds the data model (`InputType`, `Fixture`, divergence-suffix rules), `discovery.rs` walks the fixtures tree, `variants.rs` discovers variant files, `mod.rs` keeps IO/parse helpers, `validation/` is the validator (`fixtures_validate`: structure rules, per-phase checks, errors, summary — including `phases/render_equivalence.rs`, which asserts every Svelte whitespace variant *renders* like `input`, not merely that it normalizes to it), `audit_signature.rs` pins prettier's multi-pass chain.
- `test262/` — ECMAScript conformance runner: `discovery.rs` walks the test262 tree, `frontmatter.rs` parses the YAML harness metadata, `runner.rs` drives our parser (`run_test`) and grades the strict subset into the differential `Manifest` (`grade_for_manifest`, sharing the `classify` skip logic with `run_test`). Pure Rust — no Deno needed. The `test262 --emit-manifest` JSON feeds `benches/js/diagnostics/test262_compare.ts` for the tsv-vs-oxc-parser comparison.
- `tsc_conformance/` — the tsgo typechecker-conformance harness for the experimental `tsv_check` crate (pure Rust, no Deno; see ../../docs/typechecker.md for the command surface, gating status, and re-pin ritual). Three legs: the **baseline** side — `discovery.rs` walks tsgo's checked-in `.errors.txt`, `baseline.rs` parses them (`ParsedBaseline`), `render.rs` re-renders byte-identically, `query.rs` backs the `query` subcommand (the emit seam a future tsv checker uses), `pretty.rs` is the ANSI `pretty=true` model/parser/colored renderer (UTF-16 units, distinct from the plain path's runes), `roundtrip.rs` proves parse→render byte-identity; and the **corpus-input** side porting the tsgo harness — `corpus.rs` walks `tests/cases/{compiler,conformance}` (BOM/UTF-16 decode), `directives.rs` parses `// @` directives + splits `@filename` units, `options_meta.rs` is the ported option-declarations table (varyBy derivation, skip lists, tri-state, harness-forced defaults), `variants.rs` expands varyBy variants + synthesizes baseline filenames, `index.rs` runs the join/unit-text/denominator self-check gates; and the **checker leg** — `libs.rs` resolves each variant's lib set (targetToLibMap/GetDefaultLibFileName port, `@lib` override, transitive `/// <reference lib>` expansion, priority order) and caches bound lib products + per-set `LibBase` folds; `runner/` drives the `tsv_check` crate over the in-scope corpus, a directory module by concern: `mod.rs` holds the cross-cutting shared types (the graded-family table, `MissingCause`) and the three CLI entry points — `run_skeleton` = the family-conformance sweep with catch_unwind containment + the parse-divergence census, triage filters that skip pins, `--emit-manifest`, the committed `--report`, and failure `.diff` artifacts under `target/tsc_conformance/diffs/`; `check_one` backs `check-test`, the one-test dev loop; `dump_flow_dot` backs `--dump-flow` — while `filter.rs` holds `RunFilter`/`FamilyFilter`, `grade.rs` the grading/diffing kernel (`run_skeleton_inner`, `grade_test`, `grade_family`, …), `report.rs` the `SkeletonReport`/`CheckTestReport` structs + their printers, `watchdog.rs` the hang watchdog, and `tests.rs` the unit tests. `tsv_debug` depends on `tsv_check` (its only consumer — the zero-cost invariant). The exact two-sided pins are split by what they mean: the drifting tsv-side counts live in the machine-regenerated snapshot `cli/commands/tsc_conformance_pins.txt` (rewritten by `tsc_conformance run --update`, which refuses a narrowed or red run), while the semantically-zero invariant gates and the oracle-side pins stay hand-edited consts in `cli/commands/tsc_conformance/pins.rs` — plus the crash-exclusion count beside its `CRASH_EXCLUSIONS` ledger in `tsc_conformance/runner/grade.rs`.
- `cli/commands/compile_fuzz/` — the differential compile fuzzer: `anchors.rs` reads the splice offsets off tsv's Svelte parse (fragment gaps, wrappable subtrees, attribute slots, script slots, and the server-DROPPED regions — a `{:catch}` body, a `<svelte:boundary>` `pending`/`failed` snippet), `operators.rs` holds the eleven feature-level mutation operators (the cross-component donor graft, and the exotic-whitespace probe over the JS/CSS/attribute/template positions whose whitespace classes disagree), and `mod.rs` owns the generate-then-grade loop. Operators are AST/feature level rather than byte level because a compile mutant must stay oracle-**compilable** to grade anything; grading runs tsv's `compile()` first and skips the sidecar on a refusal. See [../../docs/compile_tooling.md](../../docs/compile_tooling.md).
- `diff.rs` — Colored text / JSON diffing with line-width annotations (used by `compare`, `ast_diff`, validation failures).
- `error.rs` — `DebugError` — wraps `DenoError`, `io::Error`, `serde_json::Error`; exposes `hint()` for actionable messages.
- `cli/` — argh `TopLevel`/`Subcommand` dispatch in `mod.rs` + per-command `FromArgs` modules under `cli/commands/`. Shared three-mode input plumbing (file path / `--content` / `--stdin`) comes from `tsv_cli::cli::input::InputArgs`.
- `audit/` — Shared substrate for the corpus-walking audit commands (`gap_audit`, `blank_audit`, and `ignore_audit` are the consumers of the whole substrate; `fabrication_audit`, `census_audit`, `width_audit`, and `compile_corpus_compare --ratchet` drive the ratchet alone): `ratchet.rs` (a reusable machine-generated-snapshot ratchet — the `SnapshotKey` trait + `Ratchet`/`grade`/`render`, with new-shape and stale-entry failure and a never-pinnable class for panics — plus the consumer orchestration the audits share: `Ratchet::colocated` (the one place the `src/cli/commands/<name>_known.txt` convention is spelled) + `Ratchet::path`, `refuse_narrowed_update`, `Ratchet::write_pinned`, `Ratchet::grade_and_report` (the grade→verdict→exit-status tail; a consumer needing its own — gap's yield line, blank's PANIC class — calls `grade` and prints it), `print_ratchet_skipped` and its grading sibling `grade_narrowed_strictly` — the notice a narrowed run prints instead of consulting the snapshot, split by what a finding means off the default corpus: `width_audit` has no zero to grade against (sanctioned overruns are everywhere) so it reports and exits 0, while `fabrication_audit`/`census_audit` do, so they still grade — strictly, against zero — and say so; without either line an exit-0 run with findings reads as a green gate, `report_unpinned_panics`), `census.rs` (the comment census's raw-text trivia scanners — TS/CSS/Svelte comment extraction that never consults the parser's comment carrying, the per-line-trim normalization, and the `CensusMultiset` product `census_audit` diffs), `sweep.rs` (`sweep_pristine` + `PristineSweep`, the pristine-format corpus loop every as-authored audit — `fabrication_audit`, `census_audit`, `width_audit`, `swallow_audit`, `comment_audit` — shares: `input_invalid_*` skip, read, `catch_unwind` format, the parse/read/panic skip buckets and their report tail; `sweep_pristine_armed` adds the per-file pre-format hook the two consumers that drain a process-wide instrumentation sink need (`swallow_audit`'s swallow reports, `comment_audit`'s ledger), so they share the bucketing — and the panic catching — rather than hand-rolling the loop; plus `PristineSweep::json_report(before, after)`, the five sweep fields every consumer's `--json` carries, taking both halves because the workspace enables `serde_json`'s `preserve_order` so key ORDER is observable output — four consumers lead with the sweep keys, `width_audit` leads with `print_width`, and a prefix helper would silently reorder that one), `vacuity.rs` (the two-layer guard that refuses to grade nothing: `check_graded_nonzero`, the **scope-relative** floor every corpus-walking audit calls unconditionally on the count its own VERDICT rests on — files formatted, files compared, sites probed, render keys checked — never on the count resolution returned, since the collapse it catches (every file parse-failing) lives below a healthy file list, so zero is vacuous at any scope and it needs no pin; and `check_formatted_min` + `FIXTURES_FORMATTED_MIN` above it, the **default-corpus** pin all five sweep consumers pass — one corpus and one skip policy means one number, and an audit that starts skipping differently drops below it and FAILS instead of silently absorbing the divergence in its own slack; `comment_audit` pins a second number over the same walk, `REGISTERED_MIN`, for the collapse a file count cannot see — registration stopping while every file still formats. Its own module rather than `sweep`'s, where it was born: most of its callers drive no sweep — only five do), `shape.rs` (`markup_head` + `name_run`, the markup arm of the line-shape alphabet `fabrication_audit` and `width_audit` key their snapshots on — shared so the two ratchets cannot drift into meaning different things by the same key; each audit keeps its own non-markup fallback), `sites.rs` (site enumeration + keying — `code_regions`/`svelte_internal_regions`/`injection_sites`, `string_and_template_spans` (the blank audit's string/template-interior exclusion), `regex_literal_spans` (the ignore audit's regex-body perturbation exclusion), the flat `site_shape` token key, and `source_has_ignore_directive`), `node_edge.rs` (`node_edge_key`, the enclosing-node + child-role span-containment walker behind `gap_audit --by-node`'s emitter rollup and the snapshot key of `blank_audit`'s absorb pin — the coarse companion to `sites.rs`' fine token shape, report-only in the first consumer, pinned in the second), `examples.rs` (`ExampleSet<E, N>`, the bounded N-smallest-by-`(path, offset)` example set every audit's per-shape aggregate keeps its reproducers in — first-seen tie-break, `--jobs`-invariant merge; gap instantiates N=5, blank/ignore N=1), `properties.rs` (per-input properties — the panic-safe ledger-clean `ledger_format`/`pristine_format` (whose `Clean` also carries the formatted output, so a consumer needing the pristine text doesn't format the seed twice), the shared `tsv_parse_to_value`/`structurally_equivalent`/`leaf_conservation_diff` reparse-skeleton helpers, the `Utf16ToByte` wire→byte map, and `f1_check` (the parse→format→reparse→structural→leaf→idempotency fixed-point core, shared by `fuzz` and `blank_audit`)), `report.rs` (a shared finding/verdict envelope `{audit, severity, confidence, site, example, verdict_string, detail}` keeping each audit's own detail verbatim — `Detail::Gap` / `Detail::Blank` / `Detail::Ignore`), `tally.rs` (`CappedPaths`, the exact-count + bounded-path-sample skipped-file bucket), and `parallel.rs` (`run_pool`, the stride-chunked worker-pool driver the injection audits run their per-file loop under — a worker panic outside the per-injection `catch_unwind` is a hard failure, not a silently-dropped tally; its workers take `tsv_cli::cli::stack::sized_thread`'s stated reservation (these sweeps drive the CLI's recursive descent, and an uncatchable overflow on Rust's 2 MiB default would kill the sweep) and its `--jobs` takes `clamp_worker_count`, the same ceiling `tsv format` uses. A refused thread runs its stride **on the calling thread** rather than narrowing the pool: the partition is keyed on the worker count, so a missing worker would drop a whole stride — the lost tally this driver exists to refuse — plus `ArmedRun`, the RAII arming bracket: ledger + optional swallow check + suppressed panic hook, restored on drop even on the error path), and `panic_hook.rs` (the suppressed-default-hook bracket every corpus walk that formats under `catch_unwind` installs). Ledger-touching parts compile only under the `comment_check` feature. The shared subject predicates (`is_input_invalid_fixture`, `is_ts_family`, `is_svelte` — one definition each, since the audits had drifted into three spellings of "TypeScript family" and three of "Svelte component", disagreeing on bare dotfiles) and the audits' seed-corpus resolution live in `cli/commands/profile.rs` beside `resolve_files`, imported by every corpus-walking command. Two parallel pairs over one private body (`resolve_and_keep` — resolve, keep, empty-is-error, so the walk failure and the vacuity message have one definition): `resolve_seed_files_named` (default `tests/fixtures`, the audit's own subject filter, `--limit`, empty-is-error **at every scope**) + the unfiltered `resolve_seed_files` wrapper, and `resolve_profile_files_named` (paths REQUIRED — a profiler has no default corpus — then the `input_invalid_*` split it returns as a skip count) + the `resolve_profile_files` wrapper supplying a "supported files (…)" subject rendered from `FORMATTABLE_EXTENSIONS`. Both take the filter in the same **`keep`** polarity; the profile pair used to take it INVERTED (`excluded`), so the file held two resolvers whose filter arguments meant opposite things. The `subject` parameter is what lets an audit keep a typed message — "no `.svelte` files found", "no round-trip subjects found" — while sharing the preamble; it names the set the audit will actually scan, not the raw walk. `resolve_files` is the **one** directory walk behind all of it, and its per-directory prune and per-file filter are `tsv_discover`'s (`is_safety_net` + `HEURISTIC_DIRS` + `is_formattable`), not a hand-mirrored list — the same policy `tsv format` applies, minus the ignore files, which the walk deliberately skips because the root `.formatignore` prunes the fixture trees the audits take as their default corpus.

## Distinctives

- **Three input modes, shared across most content-processing commands.** A file path (parser auto-detected from extension), `--content <str> --parser <type>`, or `--stdin --parser <type>`. The shared implementation is `tsv_cli::cli::input::InputArgs` — prefer it for new commands. A few commands deliberately take a narrower surface (`canonical_compile`, `compile_compare` and `line_width` take `--content`/`--stdin` with no `--parser`; `render_compare` takes two inputs via repeatable `--content`/paths with no `--stdin`/`--parser`; the profiling and corpus commands take path lists).
- **Sidecar wire format.** `WireRequest { id, tool, content, options? }` in, `WireResponse { id, ok, output?, error? }` out, newline-delimited JSON on stdio (the sidecar also emits a diagnostic `duration_ms` the Rust client doesn't deserialize). New JS tools are added by extending `sidecar.ts`'s `dispatch` switch and exposing a typed wrapper in `deno/mod.rs`.
- **Fixtures module is not just validation.** `fixtures/` owns the data model (`InputType`, fixture discovery, expected-file naming, divergence-suffix rules) used by `fixture_init`, every `fixtures_update*` command, and `fixtures_audit` — not only the validator.
- **The crate is one lib; `main.rs` is a shim.** Every module is declared in `lib.rs` and the binary is just `argh::from_env()` into `cli::TopLevel::run`. Integration tests in `tests/` drive the sidecar, validation, and compile-fixture logic directly through it (`deno`, `fixtures`/`validation`, `compile_fixtures`), and every module — `audit`, `cli`, `diff`, `error`, `render_normalize`, `render_browser`, `test262`, `tsc_conformance` — is declared on the lib rather than in the binary — a bin target whose name collides with the lib's is skipped by `cargo doc`, so anything declared only in `main.rs` is invisible to `deno task docs:audit` (see [../../docs/audits.md §Doc-Link Audit](../../docs/audits.md#doc-link-audit-docsaudit)). One root also means the shared modules compile once, not once per target.
- **Our formatter runs in-process.** Commands that need "ours" (`compare`, `ast_diff`, fixture validation) all call `tsv_cli::cli::format_source::format_source` — the same function the production `format` command uses — so there is exactly one definition of our formatter's output across the CLI and every debug tool.
