# tsv_arena

> The substrate tsv's three bindings share: the goal axis their exports are generated over, and the format path that prints into `tsv_lang`'s per-thread doc arena.

## Why this crate exists

The bindings (`tsv_ffi`, `tsv_napi`, `tsv_wasm`) are invoked once per file in tight loops (formatters, editor save hooks, benchmarks). Each binding's export bodies are generated from this crate's macros, so the three agree by construction on which languages have a goal axis, how a format folds and parses, and how a parse error is mapped. *Which languages have a goal axis at all* is one fact, and three copies of it agree only until one is edited; the crate's scope is the bindings' shared substrate, and its name dates from when it owned the per-thread doc arena.

**The doc arena lives in `tsv_lang`** (`tsv_lang::doc::arena::with_doc_arena`, in `doc/arena_slot.rs`): one slot per thread, shared by the bindings' format path (`parse_format!`, uncapped) and the language crates' public free `format` functions (`with_one_shot_doc_arena`, capped at `tsv_lang::store::ONE_SHOT_PARK_CAP_BYTES`), so a thread that runs both holds one arena, not two. It moved down from here so both callers could reach one slot: this crate depends on no language crate, and the language crates cannot depend on it. Its rationale (a fresh arena per call churns the allocator's heap high-water on every call, measurable through a host layer), its take/park protocol and its soundness contract (nothing borrowed may outlive the next call's `reset()`) are on that module. No parse takes an arena: every language parses into stores its own crate parks per thread.

## API

The goal-axis macros and the export bodies built on them, `#[macro_export]`ed; `parse_ast!`, `parse_ast_for_format!`, `goal_allowed!`, `parse_convert!`, `parse_internal!` and `parse_imports_json!` are feature-independent (the first three generate no code of their own; the three bodies need no doc arena), `parse_format!` needs the `format` feature and `parse_tape!` the `tape` feature:

- `parse_ast!($goalness, $lang, $source, $goal, $stores)` — the per-language parse call: every language has stores, the `*_into` entry point's `$stores`, and parses into them alone. `goal` (TypeScript) threads the decoded goal; `nogoal` (Svelte, CSS) drops it. `$lang` resolves in the *caller's* scope, so this crate depends on no language crate.
- `with_lang_stores!($lang, |stores| body)` (hidden) — runs `body` under `$lang::__private::with_stores` (the language crate's own take-and-park of its stores, since this crate can name no language type; Svelte's takes a TypeScript half and a CSS half from those crates' slots, and its own half from its own).
- `read_ast!($lang, ast, stores)` (hidden) — what a language's reading entry points take for a tree a warm parse left in `stores`: `$lang::__private::parsed_ref(&ast, stores)`.
- `parse_ast_for_format!($goalness, $lang, $folded, $goal, $stores)` — the format path's twin, over the CR-folded document (`&FoldedSource`) rather than a source string: it calls the language's `__private::parse_folded_into`, which maps a parse error back onto the caller's source and, for Svelte, refuses the one lone `<CR>` the fold would change the meaning of (`tsv_svelte::__private::parse_folded` — an `Error::refusal`, no syntax error, so each binding reports it apart from a parse failure: pointed and marked `kind: 'refused'` in the JS bindings, a plain message over the C FFI). Its `$goal` is an `Option`: `goal` calls `tsv_ts::__private::parse_folded_into`, over `parse_with_goal_or_fallback_into`, so a named source type is exact and an unnamed one takes the module-then-script fallback (see [../../docs/cli.md §Multi-File Formatting](../../docs/cli.md#multi-file-formatting)); `nogoal` drops it as above. The parse exports keep `parse_ast!`, whose goal is settled: their product is a wire carrying `Program.sourceType`, a claim no retry may make depend on the input.
- `parse_convert!($goalness, $lang, $convert, $source, $goal, $map_err)` — the C FFI's JSON parse export body (`tsv_parse_<lang>`; the two JS bindings emit no JSON wire): parse through `parse_ast!` into the per-thread stores and convert with the language's `__private::$convert` writer (`convert_ast_json_bytes`), a parse error through `$map_err`. Its `$goal` is the binding's decoded `Option`, an unset one read as `Goal::default()` (`Module`): a parse runs no fallback. No fold either — the parse wire's offsets are a contract over the caller's own bytes.
- `parse_internal!($goalness, $lang, $source, $goal, $map_err)` — the benchmark-only `parse_internal_*` body: `parse_convert!` without the convert, `Result<(), _>`, the AST held live by `black_box` inside the stores closure (the one scope where it exists — outside it the parse is dead code the optimizer may delete).
- `parse_tape!($goalness, $lang, $source, $goal, $take, $map_err, $map_tape_err)` — the three bindings' whole `parse_tape_*` body, behind the **`tape`** feature: parse through `parse_ast!` into the per-thread stores (the goal read as `parse_convert!` reads it), then write the span-only wire's tape with the language's own wire writer — its tape copy, `$lang::__private::write_tape`, the walk that writes the JSON wire — into the thread's parked sink (`tape::with_tape_sink`), finished as words (`TapeSink::finish_words`). The words are the sink's own buffer, laid out where they were written, lent to `$take` (`|words: &[u32], len: usize|`, `len` the tape's byte length) for what the binding hands its host: a copy (`tsv_napi`, `tsv_ffi`) or the address of a view over the parked buffer (`tsv_wasm`). Expands to `Result<R, _>`, `R` what `$take` returns; a parse error goes through `$map_err`, a sink refusal (`tape::SinkError` — size alone, or a writer bug the sink caught) through `$map_tape_err`. Each binding turns on the language crates' `_tape` features from its `parse` feature, beside this crate's `tape`.
- `parse_imports_json!($goalness, $lang, $source, $goal, $map_err)` — the two JS bindings' whole imports export body (`tsv_ffi` has no imports family): collect the records through the language's `__private::parse_imports_into` into the per-thread stores and write them with `tsv_ts::__private::write_imports_json_string` in the language's `WIRE_COORDINATES`, a parse error through `$map_err`. Its `$goal` is the decoded `Option`, read as a strip reads it — `goal` hands it on, so unset is the module-then-script fallback; `nogoal` (Svelte) drops it. No fold: the records' offsets index the caller's own bytes.
- `parse_format!($goalness, $lang, $source, $goal, $map_err)` — a binding's whole format export body, behind the **`format`** feature: fold the source's carriage returns, parse the folded document through `parse_ast_for_format!` into the per-thread stores, and print it into the per-thread doc arena (`tsv_lang::doc::arena::with_doc_arena`, reached as `$crate::__tsv_lang::…`), with a parse error mapped back onto the caller's own source (`FoldedSource::parse_with`) and then through `$map_err`, the binding's own error type.
- `goal_allowed!($goalness)` — `true` / `false`, read by each binding's own goal decoder (`ffi_source_type`, `napi_source_type`, `wasm_source_type`).

Plus one type and two functions:

- `Family { Parse, Format, Strip, Imports }` — which export family a call belongs to: what an unset source type means (a parse reads it as `Module`, a format, a strip or an imports parse as none named), and the noun a refusal names (`Family::noun`). `tsv_ffi`'s `ffi_source_type` reads it to accept the unspecified code from the format exports alone; the two string-axis bindings pass it to `decode_source_type`.
- `decode_source_type(source_type, allowed, family, parse_goal)` — the two string-axis bindings' shared decoder (`napi_source_type`, and `wasm_source_type` past its own not-a-string arm): unset stays unset, a source type on a goalless language and a value naming neither goal are refused, worded once for both (the npm facade restates the words in JS). A plain function generic over the goal type, the language crate's spelling table passed in, so this crate still depends on no language crate.
- `format_panic(payload)` — the text both native bindings report a caught panic with, `panic: <payload>` (`panic: <unknown>` for a payload that is neither a `&str` nor a `String`): `tsv_ffi` returns it as its error payload, `tsv_napi` throws it as the JS error's message. One spelling, so the corpus tools' panic gate (`benches/js/lib/divergence/panic_errors.ts`) reads one prefix whichever binding they load. `tsv_wasm` has no caller: its shipped profile aborts, so a panic reaches the host as a trap.

The load-bearing property is that **one `$goalness` tag drives every macro**: a language with no axis *rejects* a set goal rather than ignoring it, and the macro that picks the parse call and the macro that licenses the refusal can't come to disagree about which languages those are. Each binding still owns its own `lang_bindings!` (three different export signatures); the C FFI words its own refusals, and the two string-axis bindings share `decode_source_type`'s.

## Abort safety: take and park

The doc arena's slot **takes** its arena out of the thread-local for the call and **parks** it back after — it never holds a `RefCell` borrow guard across `f`. The argument (a WASM trap runs no `Drop` but leaves the instance callable, so a held guard bricks every later call) and its two consequences — a panicking call loses its thread's warm arena, and re-entrancy gets a fresh fallback rather than a panic — are in `tsv_lang`'s `doc/arena_slot.rs` module docs, with the tests that pin them.

What the module docs don't carry, because it is evidence rather than rationale (measured while the slot lived in this crate; the protocol moved unchanged):

- **Measured end-to-end on the built `format` bundle** with a temporary panicking export: with a held guard, a trap made every subsequent `format_typescript` throw; with take/park, calls after the trap return correct output.
- The change is **byte-identical and faster** on the WASM format path (measure with `benches/js/diagnostics/wasm_format_probe.ts`). Two effects are inseparable by construction: dropping the borrow guard, and the `const { Cell::new(None) }` thread-local init that only becomes possible once the parked state is `None` (a non-`const` initializer necessarily uses std's lazy thread-local storage — a state check per access; the `const` one is eager, on wasm a plain static).

## Features

- `format` (default) — adds `parse_format!` + the optional `tsv_lang` dep, re-exported `#[doc(hidden)]` as `__tsv_lang` so `parse_format!`'s expansion reaches `tsv_lang::printing::normalize_carriage_returns` and `tsv_lang::doc::arena::with_doc_arena` as `$crate::__tsv_lang::…` — a macro path resolves in the *caller's* crate, so a binding needs no `tsv_lang` edge for the expansion.

- `tape` — adds `parse_tape!` and the `tape` module: `with_tape_sink`, the thread's parked `tsv_lang::tape::TapeSink` (take and park, parked uncapped like the bindings' stores and doc arena), and the re-exported `TapeSink` / `SinkError` the bindings name it by. The sink's format and buffers are `tsv_lang`'s (its `_tape` and `_json` features, which this one turns on with the optional `tsv_lang` dep); the writer is the language crate's tape copy (its `_tape` feature, which each binding turns on beside this one). Each binding enables it from its `parse` feature, so the format-only builds stay blind to both. The format, the gates and the producer's rules: [../../docs/tape_format.md](../../docs/tape_format.md); the JSON → tape transcoder the gates grade every direct tape through is `tsv_debug`'s (`tsv_debug::transcoder`), never a binding's.

The **workspace dependency entry is `default-features = false`**, so a binding gets neither `parse_format!` nor this crate's `tsv_lang` edge by default and re-enables `format` from its own `format` feature. A standalone `cargo test -p tsv_arena` uses the crate's own `default = ["format"]`.

## Consumers

`tsv_ffi`, `tsv_napi`, and `tsv_wasm`. Each maps its `format` feature to `tsv_arena/format` and its `parse` feature to `tsv_arena/tape` (with the language crates' `_tape`), and builds every export body inside its `lang_bindings!` from the same `parse_convert!` (the C FFI's JSON parse alone) / `parse_internal!` / `parse_tape!` / `parse_format!` set over one `goal_allowed!` tag — the format export reaches the doc arena through `parse_format!`; `tsv_napi` and `tsv_wasm` build their two imports exports from `parse_imports_json!`. What stays the binding's own is its host's idiom: decoding the source type and building the error it reports.

For the two **native** bindings the win is heap-churn through the host FFI/N-API layer. For **`tsv_wasm`** it's the per-call `DocArena` allocation in the sandbox (the documented WASM-format allocation-count lever) — a **byte-identical warm format speedup** (measure with `benches/js/diagnostics/wasm_format_probe.ts`), with a negligible cold single-shot cost (one un-pre-sized first allocation; even `npm/cli.js` is warm after its first file) and a negligible bundle-size cost.
