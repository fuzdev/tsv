# tsv_lang

> Language-agnostic foundation crate for `tsv`

Every language crate (tsv_ts, tsv_css, tsv_svelte) depends on it for the shared parsing, formatting, and AST primitives. External deps: `smallvec`, `thiserror`, `unicode-ident`, `unicode-segmentation`, `unicode-width`, plus `serde_json` behind the `json` feature.

## Modules

Visibility in parens: private modules surface through `pub use` only; `pub mod` ones are imported directly (`tsv_lang::doc::{...}` etc.).

- `span` (`span.rs`, private) — `Span { start: u32, end: u32 }` — compact source positions
- `location` (`location.rs`, private) — public surface `WireTables` (built for a `Wire`: `Span`, or `Loc` under the `locations` feature) / `WirePositions` / `LocationMapper` / `WireCoordinates` / `WirePoint`; the tables beneath them are crate-private. `LocationTracker` (line/column over a `u32` line-start table behind a 1-entry line-range cache, so sequential emission is an O(1) range check; a miss gallops *forward* from the cached line when the offset is ahead — the writer's pre-order walk usually makes it so — and bisects the whole table only for a genuinely backward lookup. ⚠️ Three layered entry points, and the layering is measured, not stylistic: the cache hit path reads **no memory**, so a "fast path" that indexes `line_starts` instead is *slower* than a hit. `resolve_span`, the wire emitters' form, resolves a node's `start` and `end` together, searching `end` forward from `start`'s line and deliberately **not** writing that cache, so it stays parked on the descending line for the first child's `start`; an `end` that leaves its start's line is tried first against a second one-entry cache (the line the last searched endpoint landed on), since nested nodes close together), `ByteToCharMap` (byte → UTF-16 code-unit offsets as a dense `byte − utf16` **delta** table, narrowed to `u8` unless the source's multibyte characters are dense enough to outgrow it — lookup is one O(1) load, `pos = byte − delta[byte]`; an ASCII-only source carries no table: the identity map), and `LocationMapper` (the tracker + map bundle the AST-conversion layers thread — with a real map it emits final char-space positions during conversion, fusing out a post-conversion translation walk; `one_line_span_positions` is `span_positions` for a span known to lie on one line — a Svelte name, which stops at whitespace — resolving `start` alone and adding the span's width for `end`, debug-asserted against `span_positions`). `LineRule` / `WireCoordinates` name a language's coordinates (its line rule and how it counts a leading BOM — `LeadingBom`), and `WireCoordinates::point` is the one walk that answers a lone byte offset's `WirePoint` (the error path's question). Two fused constructors build a document's line table and map in one scan — `new_ecmascript_with_map` (TypeScript: CR, LF, CRLF, U+2028, U+2029) and `new_with_map` (Svelte, islands included, and CSS: LF alone). The three wire writers take a `WirePositions`, lent by the owning `WireTables`: the map, plus the line table only on the `loc` wire, built at write time — no parse path builds one, and without the crate's `locations` feature (off in every binding) the table doesn't exist, so the writers' `loc` emitters compile to dead code (see [docs/architecture.md §`loc` lines](../../docs/architecture.md#loc-lines-one-rule-per-document); `StageRun::loc_object` is their one spelling of a `loc` object, `JsonWriter::loc_field` / `span_loc` its field-level wrappers, `JsonWriter::span_start_end*` the offsets ahead of it). Both source walks are word-at-a-time — `next_non_ascii` for the multibyte splits, and for the line starts a stride over the ASCII run's words (`next_terminator_word` → `terminator_lanes`), shared by both rules (the LF rule reads only the `\n` lanes). The line scan hops words on a LOOSE test (any byte below `0x0e`: the terminators plus, in real source, the tab), confirms a hit with two **exact-per-lane** masks, then takes *every* terminator in the word from that one load, clearing the lowest lane each time. That is sound only because the kernel (`swar::ascii_zero_lanes`) carries into each lane's high bit instead of borrowing out of it — a borrowing has-zero mask's lanes above its lowest are not trustworthy, and would read a `\n` followed by `0x0b` as two line breaks. The carry is exact over an ASCII word only, so a flagged word holding a non-ASCII byte takes a cold any-byte arm (`terminator_lanes_any`: clear the high bits, then mask those lanes back out) — so the scans are exact over ANY bytes, not only the ASCII runs callers hand them, and the loose test never skips a terminator word off ASCII (it errs only toward a spurious hit). A run's last partial word is its final eight bytes with the already-covered lanes masked off; only a run shorter than a word takes a byte loop. The span-only path skips the line-start scan entirely — `WireTables` builds the map alone and emits `start`/`end` with no line/column
- `error` (`error.rs`, private) — `ParseError` with context extraction and caret formatting. **`ParseError` is a newtype over a boxed payload (`struct ParseError(Box<Payload>)`, the payload the private `ParseErrorKind` enum plus its `goal_gated` mark), so the type is pointer-sized and the enum is private** — a `const` assert pins both the 8-byte size and the `Box` niche that carries `Result<(), ParseError>` down to a bare pointer. The reason is `Result` sizing, not ergonomics: `Result<T, E>` is sized by `max(T, E)`, and the payload enum is 96 B on 64-bit (also `const`-asserted — why the context's excerpt is a `Box<str>` and its caret column a `u32`), so an inline error made every fallible function with a smaller success payload (`()`, `bool`, `usize`, `TokenKind` — the parsers are full of them) return 96 bytes through memory on its hot `Ok` path. **The larger effect is code size, not the data path**: an inline error builds a 96-byte struct into the error slot and moves it at each `?`, at every fallible call in the three parsers — cold code sharing cache lines with hot code and inflating every function's inlining cost. Boxing once, here, measured −7.0% native `.text` and −16.7% on the `parse` WASM bundle, across `tsv_ts`, `tsv_css` and `tsv_svelte` with **no signature anywhere mentioning a `Box`**. ⚠️ Never re-box at a call site (`Result<T, Box<ParseError>>`) — a double indirection, measured to buy nothing over the newtype. The private enum forces construction through the constructor fns (`ParseError::invalid_syntax` / `goal_gate` / `unexpected_token` / `unexpected_eof` / `invalid_expression`, plus `lex_err` for the lexers), which keeps `context` uniformly `None` at construction, filled later — once, debug-asserted — by `with_context(source, coordinates)`. Two errors are positionless: the size-cap error, built only by `ensure_source_fits`, and `ParseError::refusal` — a source the parse accepts but a format can't print without changing its meaning (today only `tsv_svelte::parse_folded`'s lone `<CR>` in an in-tag `//` comment), which renders its `line:col` and excerpt into its message when built but carries no `position` / `wire_point`, so no binding reports it as a syntax error (`ParseError::is_syntax_error` is the one predicate every surface asks before choosing that channel). `Display` and `Debug` forward to the inner kind, so rendered messages are byte-identical to the enum's. The context holds the error's **point** in the document's wire coordinates (`ParseError::wire_point` → `WirePoint { start, line, column }`, computed only by `WireCoordinates::point` — `start` the UTF-16 offset a wire node there would carry, `line`/`column` its `loc` under the language's line rule, a leading BOM counted or elided as that wire does) plus the excerpted display line. The message's `line:col` header prints the point, so header and binding report can't disagree; the excerpt is bounded by every ECMAScript terminator in every language (a raw CR/LS/PS mid-line garbles the terminal) and never echoes a leading BOM (display text; the header alone carries the wire's reading of it). Each language crate states its coordinates once as `WIRE_COORDINATES`, read by its parse entry points and its writer's tables (`WireTables::new`). The embedded entry points (`tsv_ts::parse_embedded` and siblings, `tsv_css::parse_embedded`) fill no context — their source is a slice, against which a host-absolute position reads the wrong text — so the host (`tsv_svelte::parse`) fills it over the whole document; until then `wire_point()` is `None`. A format entry point parses the CR-folded text through `FoldedSource::parse_with`, which maps an error back (`printing::unfold_position` remaps the position; the context is re-taken over the caller's bytes). ⚠️ **A position is a byte offset into the document the error will be RENDERED against, never into the slice that produced it** — `with_context` gets the whole document, so a position in any other coordinate space silently points at an unrelated construct. The parsers satisfy this by construction (the TypeScript and CSS parsers' `current_pos` adds its `base_offset`; the Svelte parser reads the whole document), as does the Svelte lexer (it always scans the whole document, resuming at a document offset after a jumped scan). The TypeScript and CSS **lexers** routinely scan a slice (a Svelte `<script>`/`<style>` island or template expression, the CSS declaration-value scan), so each `Lexer` carries the offset of what it scans and applies `ParseError::shift_position` **once per coordinate frame the position is lifted across** (escape-decoder digits → its backslash, literal content → the lexer's source, lexer source → the document), each lift by the code owning that frame — never again by a delegating wrapper, which would shift twice, past the end of the source, where the context clamps it and the caret lands at the end instead of on the construct. Every shift precedes the context fill (debug-asserted). Gated by `tests/lexer_error_positions.rs` and, for the escape decoder's lift, `tests/error_coordinates.rs`; no fixture type asserts an error position.

- `printing` (`printing.rs`, pub) — String literal formatting, same-line detection, visual width. The three line questions (`is_same_line_scan` / `has_newline_between_scan` / `has_blank_line_between_scan`) do a bounded scan of the source bytes, past which the document's line-break table answers — built ON DEMAND: `LineBreaks` takes the document's verdict up front (`line_terminators_are_lf_only`, one loose-needle pass: is every terminator a `\n`?) and fills its arena-parked table (one entry per terminator's LAST byte, `build_line_breaks_into`) only from the `#[cold]` fallbacks. `LineTable` is the `Copy` handle printers carry (`LineTable::EMPTY` is the canonical reprint's ERASED layout table, a distinct state answered before a byte is read). The `*_fast` forms binary-search a built table — the fallback's search and the tests' oracle; no printer calls them. The format path's `<CR>` fold (`normalize_carriage_returns`) returns a `FoldedSource` — the folded text WITH that verdict, from the fold's own pass (`classify_line_terminators`, the same loose-needle loop, recording the first `\r` and whether any U+2028 / U+2029 occurs) — which `LineBreaks::of_folded` builds on, so a folding document is walked once. Each language crate's `format_folded_in` takes it (the CLI, the three bindings, every `format_str`); `format_in` classifies the source itself. Each crate's `parse_folded` is the folded parse those entry points run; the fold also records whether it rewrote a LONE `<CR>` (`FoldedSource::folded_lone_cr`, free on a CR-free source), the key `tsv_svelte::parse_folded` reads before parsing the author's own bytes. `encode_leading_zwnbsp` is the one BOM tsv writes: `tsv_svelte` and `tsv_css` apply it to a whole formatted document whose first character is a content U+FEFF, since a UTF-8 read strips exactly one leading BOM (never to `tsv_ts`, where U+FEFF is whitespace)
- `source_scan` (`source_scan.rs`, pub) — Trivia-aware source scanning, the single chokepoint for re-scanning source between AST nodes — used by AST conversion, all three printers, the Svelte parser (which wraps `scan_to_matching_brace` for its `{…}` tags and shares `skip_template_literal` in its regex-unaware binding-pattern scan), and the TS parser's arrow-vs-paren / type-args lookahead. Its parts: the `skip_trivia` cursor ("does trivia START here") and its run-level companion `skip_trivia_run` ("where does the trivia END" — the question of a caller *between two tokens*, since a gap can alternate whitespace and comments; it owns the two obligations every hand-rolled copy of that loop had to remember — never call `skip_trivia` at `end`, step whitespace by whole characters — and takes the caller's own language whitespace class, not `char::is_whitespace`); the `find_char` / `find_keyword` / `rfind_keyword` delimiter/keyword finders (skipping JS/CSS comments + strings); the regex helpers `OperandAnchor` + `skip_regex_literal` (the `/`-disambiguation `skip_trivia` deliberately leaves out, since it needs previous-token context — `OperandAnchor` derives the regex-vs-division anchor where a `/` asks instead of tracking it per scanned byte, and is the only statement of its rule: a string or template ends an operand, a comment does not); the **hop-needle contract** every scan that skips bytes instead of asking `skip_trivia` about each must satisfy (`TRIVIA_OPENERS` + the `const`-evaluable `covers_trivia_openers`, paired in a `const _` beside each needle array so a hop that could step over a string or comment is a compile error; `trivia_hop_needles` builds the array when the scan's own byte is known only at runtime, and `is_hop_needle` is the one-byte pre-test that pays ahead of a hop whose runs are routinely empty — a pure performance choice no gate can check, so each site writes its reason); and the balanced-brace pair `scan_to_matching_brace` (the expression-context `{…}` matcher — trivia + regex + template aware) / `skip_template_literal` (interpolation-aware, since `skip_trivia`'s opaque quote-to-quote scan mis-pairs backticks across a nested template like `` `${`x`}` ``)
- `escapes` (`escapes.rs`, private) — Escape sequence handling (quote swapping) — used internally by `printing`
- `whitespace` (`whitespace.rs`, private) — `is_js_whitespace`, the ECMAScript `\s` CharSet, shared because two language crates need it and neither can reach the other (`tsv_svelte`'s `is_svelte_ws` is this set; so is the class `parseCss` skips, and `tsv_css` is a *dependency* of `tsv_svelte`). One definition, one exhaustive per-code-point test against Svelte's own hand-written enumeration. Its three trims — `trim_start_js_whitespace` / `trim_end_js_whitespace` / `trim_js_whitespace` — are the class's `trim_*_matches` answered on bytes: `str::trim_ascii*` over the five ASCII members the two classes share, then the byte it stopped on decides whether the searcher still runs (`<VT>`, the member `is_ascii_whitespace` lacks, or a non-ASCII byte — out of line and cold). One inline body per direction, deliberately: a single body over two runtime direction flags came out outlined and paid the searcher's price per call, where the inline form costs ~20 instructions per one-space trim against the searcher's ~50 — a fifth of a percent of the run at seams asked once per comment line (the directive recognizer, `is_indentable_block_comment`, `tsv_ts`'s comment renderer); `tsv_css`'s wire writer trims every declaration's property and value through the same three bodies (the space after the colon is the one byte trimmed). ⚠️ Its module doc is the **workspace-wide whitespace index** — every class in tsv, which oracle each answers to, the reads that deliberately answer to none, and the crates the `char::is_whitespace` / `str::trim` trap has been found in. Read it before adding or changing any whitespace predicate, in any crate: the recurring bug is a site's crate being taken as evidence about which class it wants
- `json_writer` (`json_writer.rs`, private, **`json` feature**) — `JsonWriter`: the byte-buffer + scalar-emitter primitive the three language crates' wire-JSON writers (`ast/convert/write/`) build on. It lives here, not in a language crate, so `tsv_svelte` can compose `tsv_ts` (embedded `{expr}` / `<script>`) and `tsv_css` (embedded `<style>`) emission into **one** shared buffer by passing `&mut JsonWriter` across crate boundaries; each language crate keeps its own node emitters. Escape/format parity is a contract: static structure and tokens are written verbatim (debug-asserted escape-free), dynamic strings are escaped by hand **byte-identical** to `serde_json`'s string serialization, non-integral `f64` delegates to `serde_json` so ryu formatting is exactly its, and integers are hand-formatted (two-digit-pair, several per node). `string` has two arms behind a **SWAR escape prescan** (`needs_escape`, over the `swar` kernels): identifier names, string-literal bodies and comment text are overwhelmingly escape-free, so a clean word-at-a-time answer turns the emission into `token`'s quote-blit-quote. The remainder is finished with an **overlapping final word** rather than a byte loop when the slice is ≥ 8 bytes, and a shorter slice (over half of all calls) is **gathered** into one word (two overlapping 4-byte loads, or first/middle/last byte) — both sound only because the answer is a boolean over the *union* of the bytes tested, so re-testing a byte can't change it (a position-returning scan must mask off lanes it already read, as `location`'s line scan does). A caller that can **prove** its string escape-free skips the prescan: `string_escape_free_led` writes a constant key and the quoted string as one fixed-width append (a quote-prefilled window, the key stored over its front, the string laid by two overlapping moves, a `truncate`); its common path makes no call — a grow or a string past 32 bytes tail-calls a cold body that does the whole write — so it keeps no callee-saved register. Users: `tsv_ts`'s identifier name (`,"name":`; an `IdentifierName` token holds no `"`, `\` or control byte by grammar) and non-string literal `raw`, and `tsv_svelte`'s `RegularElement` name (escape-free by the element parser's name gate); debug builds assert the claim at the write, and `string_escape_free_led_matches_string_on_clean_input` grades it against `string` and `serde_json`. `string_led` is its scanned twin, for a name field whose grammar admits an escaped byte real values rarely hold (a Svelte attribute or component name): the prescan is inline below a word (a longer string tail-calls `string_led_long` for the word loop — inline, its hoisted lane constants would take every callee-saved register, saved ahead of the length test on every name), then a clean answer takes the same one-append window write, key included, where `string` would pay an outlined call and a libc `memcpy` (`string_led_matches_string`). With an empty lead `string_led` equals `string`. The CSS wire writer spells every dynamic string through its variant `string_led_words`, from one shared out-of-line copy (`write_string`, and `write_keyed_string` for a declaration's `,"property":` / `,"value":`, the key folded into the write), by clean length: under a word, one window append with no call and no saved register; 8–16 bytes, two overlapping words tested as four-byte quarters (`string_led_two_words`, `escape_lanes_u32`), still no saved register; 17–32, `string_led_long`'s word prescan to the same append; longer, `string_escape_free_long`. The TypeScript and Svelte writers keep `string`, where that shape did not pay. Anything that flags goes to `string_escaped`, the hand escaper — **not** the rare arm (Svelte content text carries its line breaks and indentation; whitespace-only text bypasses it, below). It writes into a fixed-width buffer window (the `start_end` shape: extend, write through a register-held slice, truncate), moving clean bytes a word at a time with `escape_lanes`, stopping at the **lowest** flagged lane (the one the kernel guarantees genuine), then escaping byte by byte while escapes cluster; a sub-word string takes a byte loop into a narrower window. The short forms are `serde_json`'s seven (`\"` `\\` `\b` `\t` `\n` `\f` `\r`) and every other control byte is `\u00XX` in **lowercase** hex, as `serde_json` writes it. ⚠️ The prescan's predicate must stay a superset of the escaper's set (`0x00..=0x1F`, `"`, `\` — **not** `DEL`, not any non-ASCII byte), and like the integer emitters **no corpus can grade either arm**: a mis-scan or wrong escape surfaces only on an input carrying the byte, and several boundary bytes never appear in real source. The oracle is `string_matches_serde_json`, grading both arms (and `string_led` / `string_led_words` with an empty lead) against `serde_json` over an alphabet of every escaped byte and its neighbours, **at every offset across the 8-byte stride and every length to 40**, runs of escapes at every offset, and long strings crossing the escaper's window restarts — the axes a word-at-a-time scan fails on and a corpus samples arbitrarily. The escaper's window widths are exact; `escape_windows_hold_their_widest_step` drives a step to the last byte of each (a window one byte short panics there). `string_pair` is `string` for one string carried as two consecutive field values (a Svelte `Text`'s `raw` and `data`, identical whenever the decode is identity): it escapes once and copies the first field's *emitted* bytes for the second — byte-identical by construction, graded against two `string` calls over the same case set — and is `inline(always)` so its constant middle fragment stays a fixed-width move (outlined, it was a libc `memcpy` call). A Svelte `Text` of only collapsible whitespace (`[ \t\n\r]`, the indentation between tags — over half of all texts) takes `string_pair_whitespace` on the caller's word: every byte's escape is known, so no prescan and no general escaper — a counting pass fixes the escaped length, one pass stores each byte's escape (a 16-entry table built from `ESCAPE`) into both copies of a `"`-filled window, and a `truncate` cuts it; nothing reads the window back, since a wide move of bytes just written narrowly can't be store-forwarded (`string_pair_whitespace_matches_string_pair` grades it against `string_pair` over every whitespace string to eight bytes and sampled ones to 40). ⚠️ **Integer emission is arithmetic, and no corpus can grade arithmetic** — a wrong digit width writes a wrong offset that still parses as JSON, so the fixture suite, a byte-diff over thousands of files, and every audit gate can all stay green through the bug; the oracles live beside the code and must stay green. Three emission paths share one arithmetic core (`digit_word`): (1) the direct `u32`/`u64`/`usize` appends; (2) the **`start`/`end` pair** (`start_end`, and `start_end_field` / `start_end_object` with the `,"start":` / `{"start":` key — both integers and the `,"end":` key between written into one fixed-width buffer window, then trimmed; a buffer too full for the window tail-calls out, so the common path keeps no value live across a call. `start_end_tail` is the inline form for a node's whole closing burst — constant lead, key, pair and constant close in one window, no scratch for a flush to read back — taken by `tsv_css`'s hot tails; `start_end_head` is its twin for the opening burst — a literal through `"start":`, the pair and a constant close (`,"children":[`) — taken by `tsv_css`'s commonest heads; graded against `format!` over every digit-width edge pair by `start_end_family_matches_format`, `start_end_tail_matches_format` and `start_end_head_matches_format`); (3) the **staged run** (`JsonWriter::stage_run` opens a `StageRun`; its `raw` / `short` / `short_bytes` / `u32` / `usize` append — `usize_kept` + `repeat` for a value written twice, a `loc`'s start and end line — and `flush` closes), assembling a whole node header in a writer-owned scratch and appending it once. The run is a by-value cursor (scratch, output buffer, its own length), so the length stays in a register from open to flush, where a writer-held length would be a store after every fragment (each append can panic on the scratch bound, so none can be elided); that holds only while the run's address never crosses a call — hence every emitter is `inline(always)`, the two cold arms take the scratch and offset as arguments, and a helper handed `&mut StageRun` must inline too. Before touching any of the three, read `stage_run`'s doc for the measured rationale — including the point most easily gotten backwards: a run's **static** fragments are copied twice (scratch, then flush), so the trade is *appends removed* against *static bytes in the run*, **not** run width, and a wide mostly-static burst can be a net loss — and `digit_word`'s for the codegen constraints any rewrite must preserve (register-only digit generation, one magnitude test yielding both arm and width, `inline(always)` on the staged emitters). Within a run, `raw` takes a constant fragment (a fixed-width move) and `short` a static one chosen at run time (the node type), whose runtime length would otherwise lower `copy_from_slice` to a libc `memcpy` call: two overlapping fixed-width copies by length class, the same two 16-byte halves libc's AVX `memmove` uses for a 16–31-byte copy, so only the call goes (a wide inline blit, SSE2 against AVX, measured slower). `short_bytes` is `short` over source bytes (an identifier name the caller vouches is escape-free). ⚠️ Each append's **bound check** against the scratch folds away only while the compiler can bound the run's length — why the cold wide-integer arm clamps the length it hands back (`StageRun::wide`) and `short_bytes`'s inline arm restates its guard on the length it stores: no-ops at run time, the same kind of codegen requirement as `dec_pair`'s mask. A fragment with no small length bound of its own (an identifier name) is tested against `StageRun::SHORT_MAX` before staging, since one longer than the scratch would overrun it. A field whose value is one of a few literals — a boolean above all — is appended through `raw_pick` / `raw_fixed`: one literal per value, the field's key (and the constant key after it) folded in, each arm a fixed-width store because each length is its own const-generic instantiation. Spelled as per-arm `raw` calls, a large writer function lets LLVM sink the arms into one runtime-length copy behind an outlined `raw`
- `sizing` (`sizing.rs`, private) — `estimated_json_capacity` / `estimated_ast_arena_capacity` — pre-size heuristics for the wire-JSON output buffer (sized per wire: the span-only wire runs about half the loc wire) and the parse-time bump arena — plus the crate-internal `estimated_line_starts_capacity`, the capacity every `location` constructor that scans for lines seeds its line-start table at (a deliberately short bytes-per-line, so the table rarely grows at all)
- `output` (`output.rs`, private) — `OutputBuffer` — string building with column tracking
- `swar` (`swar.rs`, `pub mod` for four items) — the word-at-a-time byte-search kernels `location`'s line/multibyte scans, `json_writer`'s escape prescan and escaper, and the language lexers' token-body scans share: `splat` (the broadcast needle), `zero_lanes` (has-zero), `lanes_less_than` (has-less; the floor test of the host-range scan and of the escape prescan), `high_bit_lanes`, `zero_or_high_lanes` (has-zero OR a high bit — the loose class of `printing`'s line-terminator verdict scan, which hands a fired non-ASCII word to an exact kernel), and two kernels that are exact over an **ASCII** word — `ascii_zero_lanes` (has-zero, **exact per lane**: a carry that cannot leave its lane, so its mask may be iterated; off ASCII it fails both ways) and `ascii_has_byte_below` (has-less as a boolean, one subtract and one test; off ASCII it errs only toward `true`, never a miss) — all `pub(crate)`. One module rather than one copy per caller because their correctness argument is subtle and identical — a SWAR subtract borrows **across** lanes, so a lane's flag is not independently trustworthy. What holds is that **the lowest set lane is always genuine** (a spurious flag needs a genuine one below it, and a genuine lane always flags itself), which gives position callers `trailing_zeros` and boolean callers `mask != 0`. Read the per-kernel guarantee before adding a caller; the lowest-lane property itself is graded by exhaustive tests beside the code. **`next_byte_of`, `next_byte_below_or_of`, `has_ascii_uppercase` and `count_byte_up_to` are the four public items.** `next_byte_of` is the shape every lexer token-body scan takes (`tsv_ts`'s string / template / line- and block-comment runs, `tsv_css`'s comment run): spelled as the compare chain it reads as, LLVM emits `2 + 2N` instructions and `N + 2` branches per byte and **does not vectorize** — the caller's resume at a hit (an escape step, a `*` that opens no `*/`) makes the stride data-dependent. ⚠️ It has a **density axis**: the splats are per call and the word is per eight bytes, so break-even is ~3–4 content bytes and a construct that is routinely empty loses. Numbers, and the loose-class-plus-exact-fallback shape a non-byte-set caller uses (`tsv_ts`'s `<LS>` / `<PS>`), are on the function. `next_byte_below_or_of` is its **host-range** form — the whole document plus `[from, end)`, three classes in one word read (below a floor, non-ASCII, one of `N` needles), a lane past `end` ignored — for a "does this short slice hold any byte of a class" question: `tsv_css`'s identifier values are 10.6 bytes on average and 42% under a word, and over the bare slice such a question can only be a byte at a time. `has_ascii_uppercase` is the one class scan — "does this slice hold an `A`..=`Z` byte?", `uppercase_lanes` a word at a time, exact per lane (no borrow: the low-seven-bit word plus two constants, masked by the original high bits), its last word the slice's LAST eight bytes overlapping the one before so a nine-byte CSS property name is two word tests and not a seven-byte compare chain. `count_byte_up_to` is the one counting scan — `min(count, cap)` of a needle, each word asked first only whether it holds one (`zero_lanes`, exact as a boolean) and counted only then, by the exact per-lane kernel (`ascii_zero_lanes` over the XORed word's low seven bits, the lanes whose XORed byte held a high bit masked back out — exact for any needle, so `0x8A` is no `\n`), stopping at the word that reaches `cap`; its last word is the slice's last eight bytes with the counted lanes masked off. `tsv_svelte`'s `Text::new` asks it for a content text's newline count, which saturates at two.
- `hash` (`hash.rs`, private) — `FxHasher` + the `FxHashMap` / `FxHashSet` / `FxBuildHasher` aliases: a dep-free multiply-xor hasher for the side tables. The printer/writer tables are integer-keyed (the doc arena's `ChainShareStore` hashed tier, `tsv_ts`'s `SpanMarks`, `tsv_svelte`'s root-inline-run set and fragment-glue cache) and reach the hasher only through its integer methods; every table in the experimental `tsv_check` uses it too — address map, symbol tables and flow-label scratch on integer keys, atom interner and merge globals on **name (`str`) keys**, which route through the byte path. Replacing SipHash there is **byte-identical by construction only while every consumer stays order-free** — they use `get`/`insert`/`contains`/`clear` and never let iteration order reach output, and the `tsv_check` sites that do iterate sort first. A consumer that iterates one of these and emits in that order would make the hasher observable; that is the constraint to preserve, not the hash quality
- `census` (`census.rs`, pub, **`census` feature**) — opt-in perf census counters for a perf session: throwaway `census::add` / `hit` / `hit_if` calls at the sites being priced, labelled in `LABELS`, reported by `tsv_debug profile` / `json_profile` when built with `--features census`; plus the durable `site` hook `DocArena::concat` / `fill` feed their part counts. With the feature off every entry point is an empty `#[inline]` function, so an instrumented tree left un-reverted is inert in a default build. ⚠️ A census sizes the INSTRUCTION channel, never cycles — usage and the census-the-right-axis rules are in the module doc.

Each language parser keeps its own single-token lookahead as `peek: Option<Token>` (the lexer's own token POD), with any decoded escape value parked out-of-band — there is no shared lookahead type.

## Doc Builder

The doc builder is the core of the formatting architecture. Language printers build declarative doc trees; the shared renderer decides layout based on print width.

### Key Types

- **`DocArena`** — Contiguous storage for all doc nodes, plus the text pool (the `String` backing `Pooled`/`MultilineText` bodies) and an inline direct-mapped static cache whose slots carry two halves: the amortized-eager widths behind `text()` statics, and the per-document **interned node** — repeated `text(",")` calls within one format share one `DocId` instead of allocating per call (sound because statics are position-free at render, nodes are append-only, and no consumer keys on an interned node's identity: the identity-keyed tables, the keyed-group map and the swallow/comment side-sets key only on never-interned nodes). The hottest statics and the stateless singleton nodes — `empty()`, the four `Line` kinds, `LineSuffixBoundary`, `BreakParent`, `FlushBreak`, the flow-probe sentinel — are a **prelude** seeded at fixed ids ahead of every document (`PRELUDE` in `arena.rs`, re-seeded by `reset()`), so a literal `text(",")` or `line()` is a constant with no probe — which is why a builder *receives* a delimiter or operator as a `DocId` built at the caller (a `&'static str` parameter reaches `text()` as a runtime value and pays the prelude's mispredicting switch on every call). A `Line` node carries no mode or indent (the enclosing render command supplies both per visit), so every `line()`/`softline()`/`hardline()`/`literalline()` within one document returns one shared node. The arena also parks a per-render output scratch (`take_render_scratch()`/`park_render_scratch()`, the render analog of `pool_writer()`'s): the hot per-piece render-and-write seams (TS whole-program/per-expression, CSS per declaration, Svelte per root node) render into it through the `*_into` entry points — one warm buffer per file instead of an alloc/free per call, with an empty fresh fallback so nested renders stay correct. The render loop's work buffers pool the same way: each top-level render borrows the arena's command stack + line-suffix buffer (`RefCell`-backed, cleared at borrow); a nested render (a fill segment, a line-suffix flush) takes a second parked command stack (`take_sub_render_stack`, a `Cell` slot) and a caller-provided line-suffix buffer; the per-file line-break table parks via `take_line_breaks_scratch()`/`park_line_breaks_scratch()` (a `printing::LineBreaks` per `format_in`, filled on demand from the line questions' cold fallbacks); and the multi-line block-comment builders borrow a parked line-offset scratch (`borrow_line_spans_scratch()` — one `printing::next_lf` pass per comment fills each body line's `(start, end)` range, so the classifier and builders iterate slices with no per-comment line buffer and no line materialized as a `str`). The doc-build side pools too: wide-list builders assemble parts into a `DocBuf` from a recursion-safe free-list (`acquire_docbuf`/`release_docbuf`, or the `PooledDocBuf` RAII guard from `pooled_docbuf()`), popping a cleared buffer (keeping a prior spill's heap capacity) and returning it on scope exit, so a document's transient `SmallVec` spills collapse into a handful of long-lived reused buffers. The free-list keeps **only spilled buffers** (a release drops a never-spilled one — nothing to retain), so every pooled entry carries real heap capacity and a big-need builder can't pop a virgin buffer while capacity sits deeper in the LIFO; retained across `reset()`; allocation only, never output. A parked member-chain argument share (`chain_share_store()`, a `ChainShareStore`: an AST-node pointer → built `DocId` table) backs the TS printer's argument sharing the same way — the consumer clears it at share-scope entry/exit, so only its capacity persists. Two-tiered because it is written far more than read (96% of recorded docs are never read again on real TS code): a linear `Vec` tier for the common few-entry chain (insert a push, clear a length store), handing over to the `FxHashMap` tier on a scope's seventeenth entry (`doc/chain_share.rs`). Heuristic capacity: ~2 nodes per source byte (kept above the post-interning ~0.26/byte density because `estimated_children = nodes/2` must still clear the un-shrunk children demand); the text pool pre-sizes at source/8 (measured per-file demand p50 ≈ 0.17× source). `reset()` clears the node/child/text-pool/memo stores, retaining capacity — O(1) on the node store, since `DocNode` carries no drop glue — so a multi-file driver reuses one arena across files (the doc-IR analogue of the binding crates' `Bump::reset()`). The static cache's width halves deliberately survive `reset()` (keyed on `'static` string addresses, they warm once per arena lifetime); the interned node halves are invalidated in O(1) by the reset's `format_gen` bump. Printers borrow `&DocArena`; the caller owns the reusable one (each language crate's `format_in` is the borrowed-arena entry point).
- **`DocId`** (`u32`) — Lightweight, `Copy` handle into the arena. No cloning, no recursive Drop.
- **`DocBuf`** (`SmallVec<[DocId; 8]>`) — The single canonical doc-parts buffer every language printer (the TS chain / binary-operator printers, the Svelte template printer) assembles a node's parts in before `concat()` / `fill()`. Most nodes have a handful of parts, so the common case stays off the heap; larger nodes spill. Wide-list builders (statement / object / array / parameter / specifier lists) draw one from the arena's free-list (`pooled_docbuf()`) instead of a fresh `SmallVec` per call, amortizing the per-spill malloc/free churn (see `DocArena` above). Parts produced one at a time — a chain group's node docs, a flattened child list, a first doc ahead of its rest — go through `concat_iter()`, which pulls three parts before any buffer exists (none → `empty()`, one → itself, two → the pair arm, the rest out of line): three quarters of the buffers the printers assembled held one or two parts, and a one-part concat is its part. A site whose part count it can decide (a value and its `;`, `: T`, a bare type reference) pairs or returns directly instead. An emitter whose run is usually EMPTY (a trailing comment run, a deferred `;` run) pushes into the caller's buffer and returns what the caller needs — a cursor, a `bool` — rather than a `DocBuf`: two thirds of the printers' `extend`s were of a buffer minted, returned and consumed empty. A returning form survives only where the caller emits later than it asks.
- **`DocNode`** — Node variants: `Text`, `MultilineText` (a `\n`-separated body, one pool-stored body per multi-line block comment — rendered with per-line context indent for an indentable one, or with `literal` breaks, bare newlines keeping the interior verbatim, for a preserved one; either way ONE token to the renderer, which flushes a pending `line_suffix` ahead of it rather than at an interior break, where it would weld the two comments), `Line`, `Indent`, `Dedent`, `Group`, `IfBreak`, `Concat`, `Fill`, etc. `DocNode` carries no drop glue (`const`-asserted via `needs_drop`): dynamic text lives in the arena text pool, so `reset()`/drop never walk the node store running destructors. A companion `const` assert pins its size — **24 B on 64-bit** (the native flagship), **16 B on wasm32** (the shipped WASM bundles) — `cfg`-gated per target because it depends on pointer width (`AlignRoot`'s `usize`, `DocText::Static`'s fat pointer). The render walks the node store linearly, so the AoS layout's cache locality is the point (shrinking the node has been refuted repeatedly on this traversal-bound engine); a variant that bloats it must be a deliberate decision. ⚠️ The 24 B comes from niche-packing into `Text`'s `DocText` payload, and that packing is **charged back at every `match` over a `DocNode`**: `DocText`'s four sub-tags own discriminant values 0..=3, so a kind switch must fold them before indexing its jump table. The render loop and the fits walk peel the fold off by probing ahead of the dispatch (the `Text` test *is* the fold; in the fits walk it also retires the memo round-trip for a leaf text); the same peel is a measured **regression** in `subtree_layout_fill`, whose commonest kind sits above the fold — it pays only where the peeled kind IS the fold's range. See the comments at all three sites and [architecture.md §DocText](../../docs/architecture.md#doctext-static-pooled-sourcespan-verbatimspan).
- **`DocText`** — Four variants: `Static(&'static str)` (punctuation/keywords), `Pooled(PoolSpan)` (dynamic text, stored in the arena text pool), `SourceSpan(Span)` (verbatim source slice — resolved against `source` at print time; zero allocation for unmodified text such as identifier and element/attribute names, comments, template chunks, already-canonical literals (TS numbers/strings, CSS dimensions), and Svelte markup text, with no `DocArena` lifetime), and `VerbatimSpan(Span)` (`SourceSpan` for a **format-ignored JavaScript-level frozen slice** — identical in measurement and render, but **opaque to `will_break`**, matching prettier's `printIgnored` plain-string docs; built only via `verbatim_source_span`, only by the tsv_ts ignore emitters and tsv_svelte's braced-head value and `{@debug}` list freezes. A frozen Svelte **template** node or range is an ordinary `SourceSpan`, whose line break breaks every enclosing group, as prettier-plugin-svelte's `literalline` does). Width policy: all four (`Pooled`, `SourceSpan`/`VerbatimSpan`, `Static`) precompute their visual width at build, **with no exceptions** — name slices too: a real width (clamped below the newline flag by the one `clamp_text_width` every producer goes through) or, under `TEXT_WIDTH_NEWLINE_FLAG`, the **first line's** width, which the fits walk charges to the current line before the newline ends the measure, exactly as `MultilineText::first_width` is charged. So fits never borrows the pool and render skips its column byte-scan; `Static`'s precompute is amortized through the arena's static cache (once per unique string per arena, not per node — the same slots that intern `Static` nodes per document). Deferring a name's width doesn't avoid the scan, it moves it into `render_text`'s column advance and the fits path's on-demand measure — the two hottest functions in a format profile — and names are ~15% of all doc nodes (measuring them eagerly: `instructions:u` −0.8…−1.2% across corpora, exactly 0.000% on pure CSS, which emits none). So there is one flag and no deferral mechanism: no `NotComputed`, no on-demand measure, and **no `source` parameter in the fits walk at all** — a width question is answered from the node.
- **`LineKind`** — `Normal` (space in flat, newline in break), `Soft` (nothing in flat), `Hard` (always newline), `Literal` (newline without indent).

### Text width: the corpus cannot grade it — the equivalence test can

`pooled_text_width` (the eager precompute above) is a **search, not a sum**: the width of a plain one-column ASCII slice *is* its byte count, so one `printing::next_width_relevant` pass asks only for the first byte that could make the answer anything else — a `\t`, a `\n`, or a non-ASCII byte — and finding none has finished the measurement. 98.97% of slices never leave that scan. A hit goes to the cold `pooled_text_width_cold`, which resumes the same scan per tab, answers the newline question before the width one, and hands a non-ASCII slice **whole** to the grapheme walk.

**What a contributor must know before touching any of this: no corpus can tell you that you got the arithmetic wrong.** A width only changes the output once it crosses the print width, so an error on a rare byte leaves every formatted file byte-identical. Corrupting the tab arm by a single column was verified to pass the **fixture suite**, a full-corpus **format diff** and **wire diff** — every external gate in the repo — and to be caught **only** by the exhaustive equivalence test beside the function, which grades it against `contains('\n')` + `visual_width` on every string of length 0–3 over an alphabet covering each arm (including the control chars and the boundary-crossing grapheme clusters), and on a class byte at every alignment of every length up to 40 (the 0–3 alphabet never enters the eight-byte word loop). Keep that test green; it is the only thing that can fail.

Three traps it exists to catch. The scan mirrors `printing::visual_width`'s **ASCII fast path**, where a control character is **one** column — deliberately *not* `printing::ascii_char_width`, which counts it as **zero** and which only the grapheme-walking path uses. And a non-ASCII byte hands the **whole** slice to the grapheme walk, never the scanned remainder, because a grapheme cluster can begin on the ASCII byte *before* it. And the scan's own class: narrow it by one byte — drop the `\t` — and every tabbed text measures short by one column per tab, which no corpus can see either. The class is spelled once (`printing::is_width_relevant`) and a `const _` block proves the word loop's lane test agrees with it **at compile time**, byte by byte over all 256 — so narrowing the tail is a compile error, not a silent misparse.

⭐ **The grapheme path's own ASCII runs are a search too, and they take the OTHER class.** `printing::visual_width_mixed` — the arm a slice holding non-ASCII lands on — measures its maximal ASCII runs by finding where each *printable* stretch ends (`next_non_printable_ascii`, class `0x20..=0x7e`) and counting the bytes between hits, because a printable ASCII byte is exactly one column. **Its class is `ascii_char_width`'s, not `is_width_relevant`'s**, and reaching for the scan above is the first trap seen from the other side: that class treats a control as one column, this one gives it zero, so sharing them would over-count every string holding a control — silently, like everything else here. A second `const _` block proves this class twice over all 256 bytes (against the word loop's lane test, and against `ascii_char_width` itself), and because the corpus holds a handful of tabs and **no** other control in the ASCII runs a TypeScript format pass measures, the runtime grader is generated: each special byte at every alignment of a 0–23-byte run, with a non-ASCII tail and again with a non-ASCII lead.

### Builder API Categories

All methods take `&self` (interior mutability via `RefCell`):

- Text — `text()`, `text_pooled(&str)` (dynamic text, copied into the pool — a slice of the DOCUMENT goes through `source_span()` instead, no copy; the copy's price is the slice's length — measured ≈ 48 instructions an ask on a ~12-byte CSS selector leaf, nothing on a three-byte name *behind a guard* — and once the parser hands over the span the guard goes away, so even a three-byte name pays, as the CSS function name did once `CssValue::Function` carried a `name_span`), `multiline_text(&str)`, `pool_writer()` (streaming pooled-text assembly: a `PoolTextWriter` owning an arena-parked scratch buffer — no transient `String`, no pool borrow held open, so interleaved arena calls stay correct; consume-on-finish `finish_text()` / `finish_multiline_text()`; implements `fmt::Write`), `source_span()` (verbatim source slice — element / attribute names, comments, template chunks, already-canonical literals; width measured at build) / `source_span_plain()` (the same node for a span the caller has PROVED holds no `\t`, `\n` or byte ≥ `0x80` — its width is its byte length, so nothing is measured and no `source` is taken; reached by the identifier-name seam, three quarters of every width measure a TS format run makes, and by the verbatim-literal seam — a number is ASCII by grammar, a string's quote choice already read its bytes — which is a further 76% of the rest) / `line_comment_source_span()` (verbatim source slice, no allocation) / `verbatim_source_span()` (format-ignored JavaScript-level frozen slice — `will_break`-opaque), `empty()`
- Lines — `line()`, `softline()`, `hardline()`, `literalline()`
- Structure — `group()`, `group_break()`, `group_with_id()` / `group_with_id_break()` (a keyed group — returns its per-instance `GroupId`, whose `doc()` is the node to place), `indent()`, `dedent()`, `align_root()` (absolute tab level — template-literal root reset), `align()` (sub-tab `align(n)` — literal spaces under useTabs, tab-width-independent alignment)
- Conditionals — `if_break()`, `if_break_with_id()`, `indent_if_break()` (the keyed readers take a `GroupId`), `conditional_group()`, `gated_state()` (a conditional-group state admitted only while its probe *cannot* fit flat one indent level deeper — the caller owes that geometry; see [`DocNode::GatedState`](src/doc/arena.rs))
- Sequences — `concat()`, `concat_iter()` (parts pulled one at a time; no buffer below three), `fill()`, `join()`, `join_doc()`
- Buffer pooling — `pooled_docbuf()` (RAII `PooledDocBuf`, releases on drop) / `acquire_docbuf()` / `release_docbuf()` — reusable `DocBuf` assembly buffers for wide-list builders
- Context — `with_context()`
- Line suffix — `line_suffix()`, `line_suffix_boundary()`, `break_parent()`, `flush_break()` (flush-scoped: forces only the group the deferred run flushes in)
- Convenience — `parens()`, `brackets()`, `braces()`; the operator→value hang family is free functions in `doc::after_operator` (`hang_after_operator` / `fluid_after_operator` and their `_unindented` twins)
- Inspection — `will_break()`, `can_break()`, `as_source_span_text()` (the span of a doc that is one `SourceSpan` text, which the preserve-whitespace render entry renders as its own slice at any column — a printer writing each piece through that entry to a buffer of its own appends the slice and skips the render; `tsv_css`'s value leaf does. Not for a caller on a trimming entry, which strips a slice's own trailing space or tab). ⭐ `will_break()` and the `arena_fits` fast path share **one memo and one walk** (`DocArena::subtree_layout_fill`, cell encoding on `LAYOUT_UNKNOWN`): a forced break implies no flat width by induction over the node kinds, so both answers pack into one `u32` per node and the render-time width walk is a cache read of what the build-time break walk already filled. `can_break()` is separate — it asks a different question (*may* it break) and is newline-blind; it answers a leaf `Text` root inline (nine asks in ten on a real corpus are a plain identifier target) and its callers ask it only on the arms that read it, since the walk is the whole subtree when the root is composite.
- Transforms — `remove_lines()` / `atomize()` — rebuild a subtree with its lines statically flattened (old nodes stay in the arena, unused). **Two operations, not one function with a strength dial**, so pick by which prettier behavior you want: `remove_lines` is prettier's `removeLines` (breakable lines only; hard lines and `MultilineText` survive — it cannot promise one line), while `atomize` emulates a re-render at `printWidth: Infinity` (hard lines deleted, `conditional_group` collapsed to its least-expanded state). Atomizing is only sound where the caller has proved no newline is required — deleting a hard line fuses the content around it. A width-invariance test asserts the atomize contract: its result must render identically at every width. ⚠️ Both drop `BreakParent`, and `remove_lines` flattens soft lines **inside a group whose break flag is already set** — so a break a construct's CONTENT requires (a deferred `//` needing a line end) must be spelled as a `hardline`, never as a group flag plus a breakable line, which these erase while leaving the flag standing (`docs/comments.md` §A STATIC FLATTENER, `tsv_ts`'s `Printer::obligated_break`)
- Diagnostics — `line_comment_text_pooled()` (tags `//` text for the swallow check)

The `doc::swallow` module is a render-time guard against the line-comment-swallow bug class (a `//` emitted inline runs to EOL and consumes the following token). It sits behind the **`swallow_check` cargo feature** (off by default), so production builds compile it out entirely — no `DocArena` side-set, no render hook; `line_comment_text_pooled` collapses to `text_pooled`. With the feature, `set_swallow_check(true)` arms it and the renderer (via `SwallowTracker`) records every swallow into a thread-local sink drained by `take_swallow_reports()`. Output-neutral. `tsv_debug` forwards it as its own opt-in `swallow_check` feature (off by default so its profiles measure production-shaped render code) gating `swallow_audit` — build with `--features swallow_check` to drive `tsv_debug swallow_audit`.

### Rendering Pipeline

```
Language Printer builds DocId tree
        ↓
arena_fits_with_lookahead()  — check if group fits in remaining width
        ↓
arena_print_doc*()           — render doc tree to formatted string
```

**Rendering variants** (the `_resolved_*_into` forms are the production seam):

- `arena_print_doc()` — standard (column 0, no source: for docs with no `SourceSpan`)
- `arena_print_doc_with_indent_resolved_into()` — source-resolved render into a caller-provided buffer (full control)
- `arena_print_doc_with_indent_resolved_preserve_whitespace_into()` — same, preserving last-line whitespace (HTML pre/textarea)
- `arena_try_print_flat_into()` — not a render: writes a doc that fits the rest of its line straight onto the caller's buffer in one walk, or refuses (`false`, buffer untouched) and leaves it to the entry above, whose arguments it takes. Stands in for the preserve-whitespace entry **only** — a trimming entry would strip a trailing space this keeps — and `tsv_css`'s `write_arena_doc` / `write_arena_doc_with_suffix` are its callers. ⚠️ Its soundness is an argument about the renderer, kind by kind (`doc/arena_render_flat.rs`'s module doc): every fits call the renderer would make on an accepted doc measures only columns the walk itself goes on to charge, and those all fit, so each answers "fits". A change to what the render loop or the fill renderer does **when everything fits** — a new node kind, a new `DocContext` flag, a new side effect of rendering — must be re-read against that doc; the walk refuses unknown kinds and every flagged context, so the default is safe, and a twin (debug builds, and any build carrying an audit seam) re-renders each accepted doc and asserts bytes and column

The `_resolved_*_into` forms thread the document `source` (so `DocText::SourceSpan` leaves resolve to their verbatim slice) and reserve `estimated_output_capacity` themselves — the seam behind the per-piece writers' arena-parked render scratch. (`arena_measure_doc_flat_resolved` renders flat for *measuring* only — never written to output.)

**Below those entry points, the render path threads one `&RenderCtx`.** The mutually-recursive internals (`render_doc_iterative` → `render_doc_core` → `render_single_doc` / `render_fill_iterative`, plus the line-suffix flush) share four invariants — the arena, the `RenderConfig`, the `EmbedContext`, and the document `source` (`Option<&str>`, for resolving `DocText::SourceSpan` leaves) — bundled into `RenderCtx`, which every entry point constructs and each internal function destructures back into locals at entry, so the render logic reads unchanged.

⚠️ `RenderCtx` holds **only shared references, deliberately**. The mutable render state — `output`, `pos`, `should_remeasure`, and the command / line-suffix work buffers — stays as separate `&mut` parameters, which is why several render functions carry `#[expect(clippy::too_many_arguments)]`. Bundling those behind a struct pointer takes their address and sinks them out of registers in the hot loop; the lint suppression is the cheaper price. Don't "finish the job" by folding them in without an instruction-count gate.

## How Language Crates Use tsv_lang

### Parsing

```rust
// Language parsers use:
use tsv_lang::{ParseError, Result, Span};
use tsv_lang::WirePositions;    // What a wire writer emits positions from (root re-export)
use tsv_lang::Comment;          // Collected during parsing (root re-export)
// Lookahead is each parser's own `peek: Option<Token>` over its lexer's token POD.

// Errors enriched with context, in the language's wire coordinates:
parser.parse().map_err(|e| e.with_context(source, WIRE_COORDINATES))
```

### Formatting

```rust
// Create arena, build doc tree, render:
let arena = DocArena::for_source(source); // sized for source.len()
let line_breaks = LineBreaks::new(source, arena.take_line_breaks_scratch());
let inputs = PrinterInputs {
	source,
	comments,
	line_table: line_breaks.table(),
	has_owned_comments,
	has_format_ignore,
	comment_free_window: None, // an island printer takes the embedding printer's window here
};
let mut printer = Printer::with_context(&arena, &inputs, EmbedContext::default(), source.len());
printer.print_program(&program);
let output = printer.into_string();
```

`PrinterInputs` (tsv_ts) is the per-document environment: its flags are computed once per document — two from the comment list, the line table's verdict by one pass over the bytes (`LineBreaks::new`; its table fills only if a line question falls back to it) — never per embedded island.

### AST Conversion

```rust
let tables = WireTables::new(source, WIRE_COORDINATES, wire);
let ctx = Ctx::new(source, tables.positions(), CommentMode::Off);
```

Internal AST → wire JSON, emitted directly by the writer in one walk (tsv_ts's `write_program_bytes`; each language crate's `convert_ast_json_bytes` and `convert_ast_json_bytes_with_locations` are one-line wrappers naming the `Wire`). `Wire::Loc` (needs this crate's `locations` feature) builds the line table alongside the byte→UTF-16 map; `Wire::Span` builds the map alone. `WirePositions` carries the map so the writer emits final UTF-16 positions directly (identity/byte-space passthrough on ASCII), and `loc` iff it carries a table. A Svelte non-`lang="ts"` `<script>` goes through `write_program_embedded` with `EmbedWriter { vanilla_acorn: true, .. }` instead (Svelte's parser omits importKind/exportKind=value and always emits `attributes` on import/export declarations). That parser-variant axis (`vanilla_acorn`) lives in `tsv_ts`'s writer, not in tsv_lang — see [../tsv_ts/CLAUDE.md §Distinctives](../tsv_ts/CLAUDE.md#distinctives).

## Comment Utilities

See [../../docs/comments.md](../../docs/comments.md) for the detached model rationale, the `Comment` struct, the ownership doctrine, and the leading-comment emitter rules; the always-loaded core is [../../CLAUDE.md §Comment Handling](../../CLAUDE.md#comment-handling-detached-model).

### Lookup Functions — three questions, three names

`Comment::owned_by_node` takes a comment out of the *positional* model: the node its token
begins prints it. **Ownership is a fact about who PRINTS a comment, never about whether it
EXISTS** — so every lookup's name states which of the three questions it asks, and a miswire reads
as a category error at the call site rather than as plausible code.

**to emit** — "which comments must *I* print here?" — **skips** owned:

- `comments_to_emit_in_range()` / `has_comments_to_emit_in_range()` / `comments_to_emit_after()`
  (index twins `comments_to_emit_from()` / `has_comments_to_emit_from()`)

**on page** — "does any comment occupy the page here?" — **counts** owned. Every layout gate
(break / expand / hug / paren / fast-path / force-multiline):

- `comments_on_page_in_range()` / `has_comments_on_page_in_range()` / `has_multiline_block_comments_on_page_in_range()`
  (index twins `comments_on_page_from()` / `has_comments_on_page_from()` / `has_multiline_block_comments_on_page_from()`)

**in source** — "what comment bytes are physically here?" — **counts** owned. Every cursor
(blank-line scan, offset, `prev_end`):

- `comments_in_source_range()` / `comments_in_source_after()` /
  `comments_in_source_after_comment()` — the last from a comment the caller holds rather than
  from a position: its successors by INDEX (recovered from the reference's address in the
  slice, `ptr::eq`-verified, the search as fallback). A blank scan or a glue test asked from a
  comment's own end is a guaranteed hint miss the other way — the hint sits at that comment —
  so every such walk goes through this one and never moves the hint

Axis-free (provably): `has_line_comments_in_range()` — ownership only ever binds a **block**
comment, so skip ≡ count. If a line comment ever becomes ownable, it must grow an axis.

**The ownership lookup itself** — `owned_leading_comment_at(source, comments, start)` returns the
block comment **owned** by the token beginning at `start`, or `None`. It is not a fourth axis but
the question *behind* the split: it names the comment the to-emit axis skips, so a builder that
**replaces** a token's doc (a format-ignore freeze, a reassembled arrow signature) can print it
instead — otherwise the comment reaches no emitter at all (hazard 1). It lives here, not
twinned per printer, because both `tsv_ts` and `tsv_svelte` ask it and the answer is a pure
function of the source bytes plus the comment array — a second copy is the drift the
shared-emitter rule prevents, and has already cost one recurrence of hazard 1.

Shared:

- `find_first_comment_from()` — index of the first comment with `span.start >= pos`, and the
  **one physical entry point** all three axes funnel through. A thread-local one-entry hint
  answers the overwhelming majority of asks without searching (the printers walk a document
  in step) and falls back to a `partition_point`; the hint is **verified against the array on
  every read**, so a hint left by another document — or by an array rebuilt at the same
  address — is a miss and never a wrong answer, which is what lets it live unowned with no
  invalidation protocol and no reset. ⚠️ Its body is inlined at every site with no outlined
  copy: an instruction added there is added everywhere and re-budgets every caller's inliner
  (a twelve-line neighbour probe cost +33 KB of `.text` and cycles); a question the hint
  answers badly gets its own primitive at the sites (`comments_in_source_after_comment`)
- Every *range* lookup short-circuits a range too narrow to hold a whole comment
  (`Comment::MIN_SPAN_LEN`, guarded at the three parsers' construction sites) without
  probing the array at all — the printers ask about token-sized gaps constantly, and the
  chain grouping's member gap is the `.` alone in the overwhelming
  majority of its asks. The test is public (`range_too_narrow_for_a_comment`) so a
  printer's own existence wrapper can ask it *ahead of the call*: the compiler outlines a
  wrapper spelled at hundreds of sites, and an outlined wrapper is a call on every ask its
  first two compares would have answered, so `tsv_ts`'s wrappers are two tiers — an
  `#[inline]` gate and an `#[inline(never)]` search body (measured: ~70% of the
  narrow asks paid the call, and the split was worth 0.4% of a TypeScript format pass's
  instructions with no search spelled at any site)
- `classify_comment()` — Classify as Trailing, LeadingOwnLine, or LeadingInline
- `classify_comment_scan()` — Same, against the document's line table (a bounded scan of the source, the table as the fallback)
- `ClassifiedComments::from_index()` — Batch classify all four categories (trailing / leading × block / line) in one pass from a found first index (emit-keyed); `from_index_advancing()` advances the trailing run's anchor over each comment it takes

### Print-Once Ledger (`comment_check` feature)

Nothing in the detached model forces a parsed comment to be *printed* — a gap emitter that
never runs, an owned comment whose node reassembles off the ownership seam, a builder
handed `&[]` for its comment slice each silently lose one. `comment_ledger` is the
structural guard (tsv's `ensureAllCommentsPrinted`): each format entry point registers the
comment list it is about to print (`register_parsed`), each emission records one
(`record_emitted`), each raw source slice that carries comments out verbatim records its
range (`record_verbatim_range`), and `take_comment_ledger` reports every comment whose
emit count isn't exactly one — DROPPED or DOUBLE-PRINTED.

The **doc-based** printers (`tsv_ts`, `tsv_svelte`) don't record at build: they tag the
comment's doc node (`DocArena::tag_comment_doc`) and the *renderer* records the emit when
it reaches that node. A builder may assemble one subtree into two `conditional_group`
candidates of which only one renders, so build-time counting reads as a double-print — and
a comment built only into a *losing* candidate would read as printed while being lost.
`tsv_css`, whose printer writes comments straight to its output buffer, records at the
write itself.

Off by default (like `swallow_check`), so production builds — and default `tsv_debug`
builds, whose profiles must measure production-shaped code — compile out the registration,
the `DocArena` side-set, and the render hook. Output is byte-identical either way.
`tsv_debug` forwards the feature and gates `comment_audit` behind it; `deno task
comments:audit` drives it over `tests/fixtures` and is gated in `deno task check`.

### Directive Recognition

`is_format_ignore_directive()` / `is_format_ignore_range_start()` / `is_format_ignore_range_end()` are the single source of truth for the format-suppression directive set — the tsv-native `format-ignore` family plus prettier's `prettier-ignore` family (drop-in compat). Each operates on trimmed comment text and is called by all three language printers (`tsv_ts`, `tsv_css`, `tsv_svelte`), since the comment types differ across crates. See [docs/directives.md](../../docs/directives.md) and [docs/conformance_prettier_ignore.md §Format-ignore directive](../../docs/conformance_prettier_ignore.md#format-ignore-directive).

## Names are span-identity — no interner

There is **no string interner**. Every name a printer emits — TS/JS identifier
names, Svelte element and attribute names — is recovered from the source slice it
occupies (`source[span]`), never from a symbol table:

- **TS identifier names** (`tsv_ts`'s `IdentName`): the name is the leading
  `raw_len` bytes of the node span, re-sliced at every consumer. The rare
  `\u`-escaped or `u16`-oversized name that can't be recovered from source carries
  its decoded form as an `Option<&'arena str>` escape hatch (the parser's already
  arena-allocated `current_decoded`) — read directly, no round-trip.
- **Svelte element/attribute names** (`tsv_svelte`): `Element::name(source)` /
  `Attribute::name(source)` = `source[name_span]` — every name is a verbatim source run, a padded `{ shorthand }` included (its `name_span`
  is the identifier alone, as Svelte's `name_loc` is). No stored name field at all.

The one render-time resolution the doc builder needs is [`DocText::SourceSpan`] →
verbatim source slice (`span.extract(source)`): a printer emitting `SourceSpan` passes its
`&str` source to the `_resolved_*_into` render entry points, which thread it as
`Option<&str>` — so `source` reaches render without a lifetime on `DocArena` (the span lives
in the lifetime-less arena; the source is supplied transiently at render). No resolver
trait, no symbol variant, no deferred symbol resolution, no `string_interner` dependency.

## Config Types

`PRINT_WIDTH` / `TAB_WIDTH` / `INDENT` consts, `EmbedContext`, and `LayoutMode` are covered in [../../CLAUDE.md §Internal Configuration](../../CLAUDE.md#internal-configuration-rust-library-only). tsv has no runtime configuration.

**Embedding knobs**: `base_indent_offset` and `first_line_offset` are how tsv_svelte tells tsv_ts/tsv_css to format at the right indentation level within a Svelte component. `LayoutMode::Embedded` selects ContinuationIndent style for a binary expression at the embedded expression ROOT only (`build_root_expression_doc`); nested binaries format context-free, keyed by parent position like Prettier's `shouldNotIndent` chain. `root_sequence_indents` is the same question for a comma **sequence** at that root — a separate field, not another `Embedded` consequence, because the two positions have different oracles: prettier width-wraps a `{expr}` tag's sequence flush (so tsv matches) but never width-wraps a block head (so tsv's own geometry applies); only tsv_svelte's block-head builder sets it. `printer_owns_line` is a different kind of knob — not a layout choice but a **licence**: it says a break after this doc is still this doc's, which is what makes deferring a `//` to a line end lossless. Claimed by name (`EmbedContext::line_owning`) from a standalone document and a `<script>` body; every template island takes the safe default, since past a `{…}` the line belongs to the markup. See [../../docs/comments.md](../../docs/comments.md).

⚠️ **The width knobs act at render, `mode` acts at build.** `base_indent_offset` / `first_line_offset` / `suffix_width` are read by the renderer, so they take effect only on the context passed to an `arena_print_doc_*` call. On the context passed to a `build_*_doc` call they are inert — that doc renders later under its host's own context — and only the five build-time fields — `mode` (`LayoutMode`), `jsdoc_cast_cannot_hang`, `root_sequence_indents`, `printer_owns_line` and `value_end_takes_no_comment` — survive the trip. Setting a width on a builder's context is the recurring mistake here; check `mode` before believing a comment that attributes a layout to one.
